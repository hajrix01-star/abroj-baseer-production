Reuse resource.calendar and hr.version; preserve immutable source calendar/attendance rows. Replacement template has same name, source stores successor, replacement stores effective date; superseded source excluded from active template list, retained for historical references. Actual financial inputs unchanged; existing payroll signature check requires first-of-month if hours change inclusive salary split. Existing leave/attendance/payslip preflight reused for every affected employee; any conflict rejects entire transaction with employee context. Lock all employees in deterministic order and calendar tuple; token-guard revision fields and stale fingerprint include source and linked employee versions. Retry must not duplicate. Reject future revisions rather than change future choices. Keep existing employee direct-editor behaviour; private copied schedules remain independent, explained in UI. No fuzzy provenance migration.
