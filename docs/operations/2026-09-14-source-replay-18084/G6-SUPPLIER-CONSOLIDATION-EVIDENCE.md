# G6 — دليل توحيد الموردين وحذف المكرر

قرار المالك: حذف جهات الاتصال المكررة نهائيًا، والإبقاء على مورد مشترك واحد
لكل مجموعة في بيئة التدريب 18084 فقط.

| الدليل | النتيجة |
| --- | --- |
| نطاق المصدر | 11 مجموعة أسماء متطابقة، 33 جهة مرتبطة بمصادر نوركس، و22 جهة مكررة قابلة للحذف |
| اختيار السجل الرئيسي | سجل VAT هو الأصل عندما يوجد (مؤسسة دوحة المستهلك)؛ وإلا أقدم سجل بالمعرف فقط، بلا تخمين بالاسم المختلف |
| الحفاظ على المصدر | 35 خريطة `supplier_consolidation` جديدة تعيد كل مصدر متأثر إلى المورد المشترك؛ خرائط `supplier` الأصلية append-only ولا تتغير |
| الكاتب | addon receipt `ca133045be1bf37c09cba956037bc62657058f2b7e50271c66a42bccedfdb174`، و`replay_writer.py` `27211d81…` |
| اختبار الذرية | داخل savepoint: الجهات 366→344، run 4→5، الخرائط 1106→1141؛ ثم عاد كل شيء إلى baseline بـrollback |
| عدم الأثر المالي | بقيت الحركات=2 والدفعات=1 وstock moves/pickings=0 في كامل الاختبار |
| idempotency | الاستدعاء الثاني أعاد نتيجة واحدة ولم ينشئ أو يحذف شيئًا إضافيًا |

لا يُحذف أي سجل خارج هذه المجموعات، وأي مرجع أعمال أو قيد يمنع `unlink`
يلغي العملية كلها. لا تشمل هذه الموجة الفواتير أو المبيعات أو الرواتب.

## التنفيذ الفعلي والتسوية

منح المراجع المستقل GO بعد التحقق من 107 أعمدة مفاتيح خارجية نحو
`res.partner` من دون أي مرجع أعمال للـ22 سجلًا. نُفذ الحذف في transaction
واحدة على 18084: الجهات 366→344، وrun 4→5، والخرائط 1106→1141، منها 35
redirect مصدر. بقيت الحركات=2 والدفعات=1 وstock moves/pickings=0.

التشغيل الثاني idempotent. كل redirect من الـ35 يشير إلى أحد 11 مورّدًا
مشتركًا، ولا تبقى أي مجموعة اسم مكرر ضمن جهات نوركس المعاد توجيهها.
