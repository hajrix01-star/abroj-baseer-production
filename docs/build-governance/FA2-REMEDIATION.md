# FA2 — معالجة نتائج التدقيق وتجهيز مرشح النقل

2026-09-09. تفويض المستخدم: «عالجها حتى تصبح قابلة لنقل إلى الأصلية ... استخدم أيجنتات». التنفيذ والإصلاح والاختبار وتجهيز مرشح نقل مصرح بها. النقل الفعلي للأصلية ليس جزء هذه الجولة حتى اكتمال قبول المرشح. المرجع FA1: ../audits/2026-09-09-full/FINAL-AUDIT.md، وسجل architecture/registry الحالي.

## G0 — عقد البناء، قيد المراجعة المستقلة

الهدف إغلاق ملاحظات FA1 بالمواضع المالكة للسلوك، مع بقاء دفتر أودو مصدر الحقيقة. لا إعادة بناء ولا مكتبات جديدة. يشمل PAY-001..006، SALES-001..003، SECURITY-001..004، التحقق من تكامل الإضافات الجديدة المثبتة فعليًا والتجهيز لنقل قابل للاستعادة.

الدورة: مسودة → مراجعة واعتماد → قيد أصلي → تسجيل دفع وحالته → تسوية؛ عند الخطأ تصحيح مرتبط يحفظ التاريخ، لا تعديل صامت أو حذف حركة مرحلة. الحالات والتقارير يجب أن تميز الدفع من تصفية الالتزام. تحمي قيود المبيعات التابعة مع إبقاء عكس التحصيل المنفرد مشروعًا. الخدمة والمورد العام لهما هوية مشتركة وخصائص مالية لكل شركة. صلاحيات سطور الرواتب تتبع نطاق الأب.

القبول: اختبارات إغلاق فعلية لكل ملاحظة، ستة أشهر مع سلف وتأجيل وسداد جزئي، رفض حساب مصروف غير مناسب، اختبار موظف محدود، عدم تكرار الاعتماد أو التصحيح، مطابقة التقارير، مراجعة مستقلة ومرشح موثق. لا تغيير تلقائي للرواتب أو القيود التاريخية.

## G1 — السعة، قيد المراجعة

نُعيد استخدام قياس FA1: 50 فاتورة في نحو5ث، إنشاء شركة2.55ث، تزامن طلبين دون تكرار. هدف نطاق هذه الجولة شركة صغيرة: حتى50موظفًا بالمسير وطلبا اعتماد متزامنان، و50فاتورة بالدفعة، دون ادعاء500موظف أو حمل غير مقاس. لا زيادة في سعة المنتج أو مصدر مالي جديد. الاختبارات على قواعد معزولة فقط. النسخ: pg_dump مع filestore ثم استعادة وتحديث بإصدار محرك مثبت. القيود التاريخية محفوظة؛ التقارير مقيدة بالفترة والشركة.

## G2 — المعمارية والعقود، قيد المراجعة

ملحق G1 من قائد البناء: افتراض نمو لشركة صغيرة حتى1,500فاتورة و100ملخص شفت و50كشف راتب شهريًا للشركة، مع الاحتفاظ بالتاريخ وعدم الحذف التلقائي؛ لا تعهد سعة لعدد شركات غير محدود. هدف تجريبي ≤10ث لدفعة50فاتورة و≤15ث لتوليد مسير50موظفًا على الجهاز المعزول؛ يسجل الزمن الفعلي ويُعلن أي تجاوز بدل إخفائه. هدف الاستعادة التجريبي≤15دقيقة لنسخة البيانات والمرفقات الحالية على هذا الجهاز، وRPO مرجع snapshot المحفوظ قبل الترقية؛ كلاهما نطاق تجربة محلية وليس SLA إنتاجيًا. تستخدم التقارير ترقيم أودو الأصلي وحدود الفترة والشركة، دون تحميل التاريخ كله للواجهة.

التصنيف ARCHITECTURAL لضبط مال وصلاحيات؛ delta على عقود BP/POS/SP1 وليس خريطة جديدة. Backend وDecimal يتحققان من الإدخال، وأودو يملك دقة العملة وتوليد القيود. لا حساب مالي في JavaScript. التصحيح يستخدم ذرية المعاملة والأقفال الحالية ومرجع الأصل وصلاحية المدير، ولا يقبل context Boolean كسلطة.

fixed30: الراتب الشهري الكامل يبدأ من كامل الراتب، ويخصم الغياب وفق الأساس المحدد؛ جزء الشهر مستقل. EOS: لا تعديل تاريخي؛ يجب إظهار سياسة التقويم وتحديد حدود الخدمة بوضوح دون تقديم سياسة365 بوصفها قانونًا عامًا. يعرض مالك الرواتب خطة التصحيح قبل تنفيذ تغيير سياسة مؤثر. نصف يوم يستمد المدة المعتمدة من أودو؛ لا تحويله إلى غياب كامل. السداد والتسوية منفصلان، وتظهر حالة الدفع في البيان. أسماء عربية وإنجليزية، عناصر أودو الأصلية، لا إعادة تصميم واجهة.

## G3 — التقنية، قيد المراجعة

نفس Odoo19 والمحرك العامل، تثبيت digest بدل الوسم المتغير ومطابقة مصدر المحرك؛ Python/ORM/XML/QWeb الأصلي دون اعتماد جديد. التعديلات على ملفات المورّد إن كانت ضرورية محدودة ومحفوظة كpatch مقابل SHAالأصلي. الأمر المباشر: إصلاح المالك مع اختبارات عيب فعلي أفضل من نظام جديد. أوامر التحقق: تحليلPython/XML، تحديث الإضافات علىclone، Odoo shell tests، native RPC، تقاريرPDF ومراجعةواجهة انتقائية؛ اختبار الاستعادة مع المرفقات.

نية شريحة SECURITY-001/002/003 بعد الاعتماد: إضافة قواعد قراءة لأبناء المسير تماثل نطاق الموظف/القسم في الأب مع السماح المقابل للمدير وبقاء قيد الشركة؛ رفع قراءة metadata المحددة للبذرة فقط دون رفع معاملات المستخدم؛ إصلاح معرفي تقرير المساهمات. اختبارات native call_kw للموظف والمدير والأقسام والشركات، وخيار النوع الصريح والضمني وonchange، ثم rendering كامل للتقرير. المراجع النهائي للشريحة شخص غير منفذها.
