# رجوع الكاشير من الدفع ثم تعديل الصنف — 2026-10-01

مرجع POS-DRAFT-PAYMENT-EDIT-20261001؛ تصنيف ARCHITECTURAL محدود بسبب حماية الدفع، مالك واحد baseer_pos_product_substitution، خط أساس ae5d8963 (الموديول2.0.2). المستخدم فوّض التنفيذ وQAثمLive، دون تغيير الشاشة أو إضافة خطوات.

## العقد وخريطة الأثر

شاشة الدفع الأصلية → سطر دفع يدوي والطلب draft → الرجوع → أمر التعديل/الإلغاء القائم → قفل الطلب ثم سطور pos.payment بترتيب id → إعادة قراءة وتحقق revision والصلاحيات والشركة والجلسة → تحقق البدائل/المصدر → إزالة السطور المبدئية الآمنة داخل savepoint → تعديل الصنف وحسابات Odoo الأصلية → حدث التدقيق الحالي ونتيجة canonical → تنظيف سطور الدفع المتقادمة من الذاكرة وIndexedDB قبل إعادة التحميل. التأكيد النهائي للدفع والمحاسبة يبقيان في مسارات Odoo الأصلية.

الآمن: draft غير مرتجع، جلسة opened، بلا invoice/session_move أو مبلغ إرجاع؛ payment.amount غير سالب، بلا is_change/account_move/status أو بيانات بطاقة/مرجع/معاملة/ticket، طريقة cash/bank بدمج none ولا terminal/online hook، amount_paid يطابق مجموع السطور. أي نوع أو أثر غير معروف يرفض. quotation يتحقق فقط ولا يحذف؛ apply المقبول فقط يحذف ويسجل id/uuid/method/amount داخل source_snapshot الحالي. إعادة المحاولة لا تمس دفعة جديدة، والتعديل المتزامن للدفعة يفرض rollback/retry. لا رفع صلاحية payment/طلب/مستخدم ولا schema أو RPC أو ACL جديد.

## المراجعة والبوابات المتناسبة

G0/G1: الهدف والخريطة القائمة مثبتان؛ لا إعادة تصميم UI أو بنية تطبيق. G2: المراجع المالي المستقل permission_review اشترط قفل سطور payment ورفض _is_online_payment()؛ أُدرجا في العقد قبل التنفيذ. G3: رصة Odoo والمكتبات الحالية، لا تثبيت أو اعتماد جديد. بقية التدقيق يقتصر على أثر الدفع والتزامن والرحلة. السعة: القراءات محصورة بسطر الطلب الحالي ومدفوعاته، قفل id مرتب مع القفل الحالي، لا مسح سجلات/ترحيل أو ادعاء حمل.

مصفوفة القبول: كاشير فعلي مع إخفاء السجل؛ cash/bank وzero/partial/multiple؛ quote دون حذف؛ تعديل ثم إتمام دفع؛ إلغاء صنف وإعادة حساب المستحق؛ paid/done/terminal/QR/online/accounting/refund/negative/change/metadata غير مؤكد ممنوعة؛ stale/failure تحفظ الصفوف؛ retry لا يحذف دفعة لاحقة؛ تنظيف cache يمنع إعادة السطر؛ تزامن مباشر لحالة/مبلغ الدفع مقابل cleanup بمعاملتين. baseline failing → candidate tests → مستقلGO → سياسة موديول واحد → QA → Live بنفس مصدر Git والغلاف المحمي مع زوج استعادة. لا طباعة فعلية ولا طلب اختبار في Live.
