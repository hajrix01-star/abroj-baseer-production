# PAD1 — Print agent diagnostics

## Contract / G0–G3 evidence

Owner request: upgrade our agent with ready, actionable error evidence rather than repeated investigations. Candidate starts from official/main c8fa9bef7, independent codex branch. Odoo remains sole receipt/kitchen designer. No sales/accounting writes, server schema changes, new dependencies, automatic reprints, or external package code.

Critical journey: claim → durable in-flight → validate/decode → monochrome → Windows submission → Odoo acknowledgement. Each transition has job ID and stable stage/error code; exception type/HResult only. No exception text, HTTP bodies, token, config, customer content, or arbitrary path in exported events. Windows acceptance never means physical paper confirmation. Diagnostics are best effort and cannot alter lease/print outcomes.

Capacity assumptions: tens of installed PCs, one executing job per process; target diagnostic event append under 20ms locally, bounded 2×1MiB event files, last 200 events in UI/export, no unbounded queue enumeration. Capture is explicit, off by default, local protected directory, at most 3 jobs/15 minutes and 20MiB with 24h expiry; images never included in default export. No shared/live load test: change is local file/event/UI handling, existing workload sequential, verify bounded synthetic rotation instead.

Architecture: existing .NET8 Windows Forms + System.Drawing + Windows spooler native APIs. Add local event store, native status/export window, opt-in raster capture, read-only correlated queue observation. No localhost listener. Retain existing durable in-flight and runtime mutex. A queue error is evidence, not permission to reprint; unknown remains unknown. Existing updater and profile isolation reused. New version 1.5.22.

Direct path decision: extend the current process, built-in WinForms controls and protected data directory. Replacing transport with RAW or external package does not solve the established raster-to-paper discrepancy and changes risk unnecessarily. Official Windows JOB_INFO_2 documentation: COMPLETE and even PRINTED do not universally prove paper output.

Acceptance: build Release and QA; deterministic no-printer tests for redaction/rotation/export/capture expiry/error classification and pixel preservation; manual/native UI inspection; independent review of diagnostics isolation and no-reprint semantics. Real QA/physical acceptance must be reported separately, never inferred from compile/tests. Publish/registration follow PRINT-AGENT-RELEASE-PROCESS, protected deployment only.
