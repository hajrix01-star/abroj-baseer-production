## G2-C17 — استهلاك التفضيلات الشخصية، مسودة قبل كود Android

هذه توسعة للعقد الخلفي المقبول، وليست موافقة ذاتية أو تغييرًا للبيئات. قبل الربط يلزم GO مستقل على النقاط الآتية:

- التفاوض: حقل bootstrap علوي إضافي `room_preferences_contract_version:1` فقط؛ لا capability جديدة true ولا probing يفعّل ميزة. العميل القديم يتجاهله؛ غيابه/قيمة غير مدعومة تبقي القائمة القديمة وتخفي أدوات C17 دون وصف الخدمة offline. إعلان الإصدار يعني اكتمال مسارات التفضيلات والقائمة وأهلية المستلم الحالية، لا قبول جهاز.
- مرجع العضوية: `/rooms` الكامل يبقى مصدر المصادقة/الشركات/حقبة العضوية وcache.reconcile وC13. `/social/rooms` projection شخصية فقط، لا تمرر قائمة مفلترة إلى purge أو كشف فقد العضوية. المؤرشفات لا تُقرأ أو تُكتم أو تُحذف تلقائيًا، ولا يلغي وصول رسالة أو فتح تنبيه الأرشفة. لا عداد صفر مؤكد قبل اكتمال صفحات الأرشيف.
- المسارات الحالية فقط: GET preferences بـmembership_id؛ POST form وحيد csrf_token,payload بلا query؛ وGET social/rooms بـarchived/cursor. حدود الخلفية30 صفًا و128KiB، cursor≤512ASCII، وPOST≤8KiB باقية. لا cursor مفكوك من العميل ولا endpoint عام للكتابة. full payload ثابت الحقول مع IDs/revisions موجبة وbooleans حقيقية وUTC20 أوnull.
- فصل التنفيذ: Protocol immutable وصارم؛ Store metadata-only؛ Controller يملك النية والتصالح؛ Panel بـHost ضيق؛ وprojection للقائمة. Activity يمرر عمليات الجلسة الحالية وحواجز الهوية/الجيل، دون زيادة منطق CAS داخل القوائم. فتح التفضيلات من صف الغرفة لا يفتح الرسائل أو يرسل read.
- نية واحدة لكل account/room/membership؛ حتى20 نية معلقة/حساب، وحتى100 لقطة تفضيل مؤكدة للعضويات الحالية. ملف AtomicFile خاص منفصل لكل AccountScope، حد256KiB للـUTF8 المقنن يشمل اللقطات والنوايا والأخطاء المحدودة. أرقام/UUID/حالات/حقبة/أزمنة فقط؛ لا اسم/نص/صور/توكن/CSRF. هذه حدود محافظة مشتقة من100غرفة وحد20نية المعروفين، لا قياس حمل أو وعد سنوات.
- كل القراءة/الكتابة على عامل التخزين مع قفل store واحد، ولا I/O تحت ROUTING أو علىMAIN. commit النية يسبق dispatch؛ امتلاء/فساد/فشل حفظ يمنع كتابة الشبكة ويعطي حالة مفهومة، ولا يُسقط نية غير محسومة. إذن UI ليس برهان commit. تحفظ النية UUID والpayload كاملين كما أُرسلا، وتُعاد بهما فقط بعد timeout/restart عندما تبقى الهوية والعضوية والحقوق الحالية صالحة. stale callbacks يمكنها تسوية عملية مثبتة في store لنفس الهوية فقط، ولا ترسم شاشة جديدة.
- replay يعيد snapshot الحالية وoperation_revision الأصلية: لا نفرض مساواة revision بالعملية أو مطابقة الحالة للاختيار القديم. إقرار UUID الصحيح يثبت العملية؛ الحالة الحالية الأعلى تبقى مرجع العرض. 409 revision_conflict يلزم GET حديثًا وقرار مستخدم جديد قبل UUID جديد، بلا retry overwrite تلقائي. membership_changed/403 تمنع dispatch وcross-epoch replay، وتظهر نية غير متاحة للمراجعة؛ لا تُنقل للعضوية الجديدة. حقوق مسح الكاش لا تخترع إقرار نجاح لعملية.
- pin/archive جديدان يُبنيان من GET حديث؛ muted_until المنتهي يُقنن إلىnull في **نية جديدة فقط** دون تعديل payload معلقة. pinned_at من الخادم. لا يجبر العميل ترتيبًا مخالفًا: pinned ثمpinned_at ثمlast_message_id ثمroomID تنازليًا. صفحات projection ليست snapshot؛ refresh يبدأcursor0، و409 يعيد التحميل دون دمج قائمتين غير متوافقتين.
- كتم محافظ: طلب mute يضع حاجز RAM محليًا فورًا، ثم لا dispatch قبل الحفظ. فشل الحفظ يبقي حاجزًا مؤقتًا معلنًا حتى رجوع الحالة المؤكدة/إلغاء المستخدم، لا نجاحًا كاذبًا. pending unknown لا يصبحunmuted بسبب مهلة أو expiry مفترضة. unmute لا يرفع الحاجز قبل إقرار الخادم وحفظه. بعد بدء العملية يعاد فحص الحساب والعضوية/الجيل عند كل أثر، ولا تكتم غرفة حساب آخر أو حقبة جديدة.
- FCM المتأخر يحتاج عقدًا مكمّلًا قبل ادعاء كتم محلي كامل: الحقول الاختيارية `mute_scope_v="1"` و`mute_room_key`64hex للـchat ولمهمة مرتبطة بغرفة فقط؛ من اشتقاق room_key الحالي نفسه لهوية **المستلم** وعضويته. بلا اسم/معرّف غرفة خام/صلاحية جديدة. المهمة المستقلة لا تحمل نطاق غرفة ولا تُكتم بكتم غرف أخرى. يتأكد الخادم من الأهلية قبل الإضافة، ويعيد فحص mute الحالي عندdispatch كما الآن. العميل يعيد فحص مرآةRAM تحتROUTING قبلappend/notify/نغمة، بلاHTTP/قرص؛ الحقول ليست تفويض وصول.
- حدود القديم: payload قبل العقد قد لا يحدد نطاق مهمة؛ لا نختلق هوية ولا نكتم كل المهام. الضمان المحلي للسباق يخص scoped payload الجديد فقط، وتبقى إعادة فحص dispatch وحماية الحقوق قائمة للجميع. إلغاء إشعار غرفة أصبح مكتومًا يُطابق نطاقًا محليًا في extras للإشعارات المملوكة فقط، لا cancelAll؛ لا تعديل عام لقنوات Android أو أصواتها.
- لا codec أو WorkManager أو مكتبات جديدة، ولا تعديل تاريخ/إيصال/مجموعات مشتركة أو outbox رسائل. قبول protocol/store يكون منفصلًا عن ربط UI/FCM، والتسليم يظل واحدًا. يلزم source review وRED/GREEN عند اكتشاف عيب، nativeAtomicFile/kill-restart، commitfail/lostACK/replay superseded/409/rejoin/account-switch/archive≠purge، وAR/EN/font2. لا قبول صوت/OEM منمكيفات أو مجردnotify.

تصحيحات G2-C17 بعد المراجعة المستقلة، ناسخة لأي تعارض في المسودة أعلاه:

- الإقرار يتطلب رد200 موثقًا يطابق api/room/membership/UUID و`operation_revision=expected_revision+1` و`revision>=operation_revision`؛ عندreplayed=false يتساويان. لا يُرجع snapshot محفوظة أحدث إلىrevisionأقدم، ولا تُعاد نية قديمة فوق replay superseded. نفاد revision يمنع نية جديدة بدل overflow.
- تقنين expiry ورفع حاجز timed-mute يستندان إلى GET خادمي حديث يعيدmuted=false، لا إلىساعةالهاتف وحدها. لا تغيير payload معلّق، والإلغاء المحلي لا يرفع حاجز نية سبقdispatch لها وظلت مجهولة.
- حد20 يشمل المحجوبة وغيرالمحسومة.100snapshot للعضويات الحالية فقط. حد256KiB والبنية يُتحققان عندالقراءة والكتابة، والأخطاءcodesمحدودة لاrawservermessages. قفل القرص process-wide لكلAccountScope، ولاpublishإلىROUTING أثناءحمله؛ نشرRAMبعدتحريرهوبإعادةفحصملكيةالجيل.
- حقلاmute كلاهماstringsويضافان قبل حساب حد3072UTF8 النهائي؛ pair/version/hash صارمة. chat يطابقmute_room_key معroom_key الحالي. accountUUIDالمسجل وعضويةالمستلم هما مصدرالاشتقاق؛ لاAccountScopeSHAأوعضويةالمؤلف أوأسماءإضافيةعندnone/sender.
- تتبع scope metadata محليًا مع(tag,id) **قبلnotify**، بما فيهqueuedrowsغيرالظاهرة؛ إلغاءknownscopeثمactiveصفوفالعمليةالسابقة دونcancelAll، معحفظالفشلواختبارالتوقيت. scopedpayloadالمتناقض/ناقصpair/غيرمدعوم يُرفض عرضه دونصوت؛ الغيابالقديملكلاالحقلينفقطلهfallbackمحدودمعلن. هذا لا يمنحهويةPayloadسلطةحقوق.
