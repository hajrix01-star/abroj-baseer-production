One fetch reused for preview, print and download; no regeneration or business mutations added. Native reporting may perform its existing attachment caching. Callback only after report prepared and user closes preview; cancellation before ready must not claim success.

Existing PDF.js not automatically loaded; download remains fallback when browser cannot print. Direct path decision: reuse native /report/download, no HTML reconstruction, no extra rendering service. Prior research sources: MDN Window.print and official Odoo19 report/controller/action source already examined. Tests: transport/options/context, non-PDF pass-through, PDF validation, load failure/abort/lifecycle, explicit download, responsive native dialog, actual QA Arabic/multipage PDF and browser UI. G4: existing native Dialog/buttons, compact wrapping footer, responsive iframe; AR/EN translation. No new design system or animation. Controls remain available if auto-print is blocked.
