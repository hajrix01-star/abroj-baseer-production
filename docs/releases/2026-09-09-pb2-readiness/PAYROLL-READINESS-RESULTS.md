## Test corrections and practical limits

Initial test iterations exposed an Officer computed-read compatibility defect, missing `odoo-python` PO markers, and a long badge. These are corrected and the relevant final checks pass. The first future-version test accidentally included previously future employees when advancing to March; the fixture scope was corrected. The first RPC context probes used record context alone, which native `call_kw` replaces; final probes supply `kwargs.context` explicitly. The initial default-flag result is therefore **not** claimed as a proven exploit. The final guard and both authorized/unauthorized contexts are tested.

The race harness retries native PostgreSQL serialization/deadlock failures in fresh transactions. The final HR/approval race observed `DeadlockDetected` then `SerializationFailure`, resolved within three attempts; refresh observed one serialization retry. No deadlock-free claim is made, and this bounded two-request evidence is not a stress test. The earlier successful opposite ordering preserved an already posted salary after HR changed the source; the final retained race artifact demonstrates HR-first ordering, while the matrix independently checks preservation after posting.

No bulk data migration or mass employee enabling was added. Source history and native contract permissions are retained. PB2 does not certify EOS legal compliance, alter FA2's historical/Gregorian policy, create legal contracts, install signing software, or test unrelated modules. UI and deployment acceptance are documented separately by root and the independent reviewer. These results support the tested contract, not a claim that the entire system has no defects.
