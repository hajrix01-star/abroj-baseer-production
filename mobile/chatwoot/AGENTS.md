# BWork — الحفاظ على السلوك المعتمد

هذه تعليمات خاصة بهذا التطبيق، تكمّل تعليمات المستودع ولا تستبدلها.

## النسخة الحالية المعتمدة كمرجع مستقر

اعتمد المالك في2026-10-19 النسخة **0.1.20/build21** مرجعًا مستقرًا للتطبيق الحالي (المحادثات والطلبات والاستلام والهوية والتنقل). مصدر APK المجمد `bb3e69c18ac504997c00afbb8bb347b06b97ce02`، والوسم المحلي `bwork-stable-0.1.20-build21` يشير إليه. صفحة التوزيع ودليل APK في `docs/architecture/registry/INDEX.md` على مستوى المستودع، وسجل الإصدار `docs/build-governance/BWORK-SILENT-ALL-COMPANIES-20261019.md`. الاعتماد مرجع منتج وعدم تراجع، ولا يغلق فجوة التحقق من نتيجة تحديث خادم QA أو يحوّل إصدار QA إلى إصدار Live.

- لا يُغيَّر السلوك المعتمد في المحادثات أو الطلبات أو الاستلام أو الهوية ضمن إضافة قسم المهام. القسم الجديد مستقل؛ أي فرق لازم في التنقل أو الجلسة المشتركة يحدد ويبرر قبل التنفيذ ويغطيه فحص عدم تراجع متناسب.
- طلب المالك الحالي لقسم المهام **دراسة المصدر القديم وشرح آليته فقط**؛ ليس تفويض تنفيذ أو بناء APK أو تعديل خادم أو بيانات. التنفيذ اللاحق يحتاج طلبًا صريحًا ومسار البناء المناسب.
- يبقى مرجع المحادثة0.1.16/build17 (`7afe86bc8adb8e4714f8a2b753561fa5e3912552`) تاريخيًا، والنسخة0.1.20 المرجع الأحدث للتغييرات المعتمدة بعده. لا يمحو اعتماد المرجع الحالي الخصائص المحمية في السجل التراكمي.

## المحادثة المعتمدة والمجمّدة

- لا تغيّر شكل المحادثة أو ميزاتها أو سلوكها أو تخزينها أو إرسالها أو صوتها أو صلاحياتها بلا طلب صريح من المالك. لا تعتبر بناء قسم جديد إذنًا لتحسين المحادثة أو إعادة هيكلتها.
- الأقسام الجديدة، ومنها الطلبات، تبقى بوحداتها المستقلة. أي تعديل لازم في هيكل التطبيق أو التنقل المشترك يوثق بفرق محدود، ويحافظ على عقود المحادثة المعتمدة ويخضع لفحص عدم التراجع؛ لا يُضمَّن تغيير داخلي للمحادثة ضمنه بصمت.
- عند اكتشاف عطل أو ثغرة في القسم المجمد: أبلغ المالك بالدليل والأثر واقترح التغيير المحدد؛ لا تخفِ المشكلة ولا تنفذ إصلاحًا خارج النطاق دون تفويض. لا تُنقص الاختبارات أو الثوابت لتمرير قسم آخر.
- هذا تجميد عمل وتعليمات مراجعة محلية، وليس منع كتابة على مستوى نظام الملفات أو ادعاء تفعيل حماية الفرع في GitHub. لا تُعدّل إعدادات الحماية البعيدة ضمن هذا الاعتماد.

- مرجع الخصائص المحمية الوحيد: `tools/bwork-baseline.json`، وطريقة العمل: `docs/BWORK-REGRESSION.md`.
- قبل تسليم أي تعديل شغّل `npm run check:bwork` (أو `pnpm run check:bwork`). يفحص الأنواع والاختبارات الحالية ويتأكد أن اختبارات الثوابت نُفذت ونجحت فعلًا؛ الاختبار المحذوف أو المتخطّى ليس نجاحًا.
- لا تحذف ثابتًا معتمدًا أو تضع اختباره في skip/todo لإمرار الفحص. تغيير السلوك المعتمد يحتاج طلب المستخدم أو موافقته، ثم تحديث الثابت واختباره معًا وذكر الأثر.
- كل خاصية جديدة معتمدة أو عطل مُصلح قابل للاختبار يضاف له اختبار سلوكي صغير؛ اربطه بالسجل إذا كان من الثوابت العامة. لا تنشئ نسخة ثانية من اختبار موجود يكفي للحماية.
- في تغييرات الواجهة افحص الحالة والشاشة المتأثرتين فقط بالعربية والإنجليزية والعرض الضيق، وقارن بالمرجع المعتمد المناسب. الاختبارات الآلية لا تثبت المظهر الفعلي أو موضع الكيبورد على جهاز.
- لا تعِد اختبار السعة أو الترحيل أو الخلفية عند تعديل شكل محلي. تغييرات التخزين/العزل/الصلاحيات/الإرسال تبقى خاضعة لفحوص الخطر الخاصة بها.
- الفجوات المعروفة في `openGaps` ليست ميزات ناجحة ولا غيابًا معتمدًا. لا تضف اختبارًا يفرض استمرار فقدان ميزة. شخّصها ولا تنشر إصلاحًا غير مطلوب.
- هذا الأمر بوابة محلية وتعليمات تسليم، وليس ادعاءً بوجود حماية GitHub/CI مفعّلة أو ضمان صفر أخطاء. لا تنشر APK لمجرد نجاحه؛ التوقيع والمصدر والترقية والقبول الأصلي تبقى ضمن مسار التسليم المعتمد عند طلب نسخة.
