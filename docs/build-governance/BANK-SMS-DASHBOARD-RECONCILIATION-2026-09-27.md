# مواءمة لوحة تحليل بصير SMS — 2026-09-27

## G0 — عقد التعديل

- **الهدف:** جعل إجماليات لوحة التحليل قابلة للمطابقة الصريحة مع كروت
  المعرّفات والرسائل ضمن الفترة نفسها، من دون الإيحاء بأن حركة الرسائل رصيد
  مصرفي أو حركة محاسبية.
- **المشكلة المثبتة في QA:** الملخص العام يضم الرسائل التي لا تحمل معرّفًا
  وكذلك المعرفات غير النشطة، بينما الكروت تعرض المعرّفات النشطة فقط. الكرت
  نفسه صحيح لنطاقه، لكن العلاقة بينه وبين الملخص لم تكن ظاهرة. كما كان فتح
  الكرت لا يقيّد الاتجاه كما يقيّده احتساب المبلغ.
- **النطاق:** `baseer_bank_sms` فقط: عقد قراءة لوحة التحليل، واجهة OWL/QWeb
  الخاصة بها، واختبارات Odoo المركزة.
- **خارج النطاق:** تعديل أي رسالة SMS أو معرّف أو بطاقة أو شركة أو قاعدة
  توجيه، وإنشاء أو تعديل قيد/دفعة/يومية/تسوية/حركة بنكية أو أي بيانات تشغيلية.
- **معايير القبول:** لكل عملة وفي عوامل التصفية نفسها: إجمالي الرسائل =
  مجموع كروت المعرّفات النشطة + رسائل بانتظار التعريف + رسائل معرّفات غير
  معروضة إن وجدت؛ وتطابق نتيجة فتح الكرت مبلغ الكرت وعدده واتجاهيه؛ وتبقى
  العملات منفصلة ويُحسب المال في الخلفية فقط.

## G1 — السعة

مصدر القراءة هو تجميع `read_group` واحد بحسب المعرّف والعملة والاتجاه؛ لا
قراءة رسالة في حلقة ولا مهمة خلفية ولا كتابة. قاعدة QA المرجعية تقارب 748
رسالة؛ معيار القبول استجابة اللوحة في أقل من ثانيتين في QA مع بقاء الأداء
محدودًا بتجميع Odoo المفهرس.

## G2 — المعمارية وسلامة الأثر

رسالة `baseer.bank.sms.message` هي مصدر الحقيقة. العقد يعيد دلاء قراءة
مستقلة: كل الرسائل، كروت المعرّفات الظاهرة، بانتظار التعريف، والمعرّفات غير
المعروضة. لا ينفذ العميل جمعًا أو تقريبًا ماليًا، ولا توجد RPC للكتابة من
اللوحة. تعتمد صفحة الرسائل المنبثقة نطاق التجميع الخلفي نفسه.

## G3 — التقنية والتجربة

لا اعتماد أو نموذج جديد. يستعمل التعديل Python/Odoo `read_group` وOWL/QWeb
وSCSS الموجودة. النص عربي/RTL، مع بقاء التمرير والجوال ضمن فحص القبول. لا
تُعرض الدلاء الخالية كإنذار؛ يظهر فقط ما يلزم لشرح المطابقة.
