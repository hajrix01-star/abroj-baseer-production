# مراجعة تسليم WS4 — تعديل جدول العمل

التاريخ: 2026-09-09. المراجع المستقل: `schedule_edit_review`. مالكا التنفيذ: قائد البناء و`schedule_edit_backend`. منفذ الاختبارات المستقل: `schedule_edit_tests`؛ اختبارات الانحدار والواجهة والتشغيل لدى قائد البناء.

## الحكم الحالي

**NO-GO للإطلاق في هذه المرحلة بسبب اكتمال الدليل فقط:** مراجعة الكود وG5 وG6 مقبولة، ولا يوجد عيب P0/P1 مفتوح في نطاق WS4. يلزم قبل PREDEPLOY-GO تثبيت مرشح المصدر وhash الأرشيف، والتحقق من مطابقته للكود المختبر، وإكمال دليل الواجهة العربية والإنجليزية على الكمبيوتر والجوال. لم ينفذ هذا المراجع أي تغيير في MAIN.

هذا حكم خاص بإضافة تعديل الجداول، وليس اعتماداً شاملاً لكل النظام أو إغلاقاً لقرارات سياسات الرواتب السابقة.

## النطاق والخريطة

الأساس هو WS3 بالمرشح `40dee029c01cf51fa01d233185b3b63805754ce3`. التغيير محصور في addon `baseer_work_schedule`، الإصدار `19.0.1.1.0`. المقارنة مع مصدر WS3 المحفوظ أظهرت أربعة ملفات متغيرة: manifest، نموذج الجدول، XML الواجهات، والترجمة العربية. لا تغيير في المكتبات أو Odoo أو محرك الرواتب أو أصول منتقي الوقت.

رُوجعت خريطة الملكية القائمة في `docs/architecture/registry/INDEX.md`؛ تظل نماذج Odoo والرواتب الأصلية مالكة البيانات والحسابات. الرسم التالي فرق WS4 الموضعي المبني على الكود المقروء، وليس إعادة اكتشاف النظام:

```mermaid
flowchart LR
    U[مدير الموارد البشرية في نموذج Odoo] --> W[معالج الجدول المبسط: تاريخ وأوقات]
    W --> V[صلاحيات وشركة وبصمة ومراجعة التاريخ]
    V --> L[قفل الموظفين ثم لمس صف التقويم]
    L --> C[تقويم بديل ثابت وسلسلة تعاقب]
    L --> E[نسخ hr.version بتاريخ النفاذ]
    C --> E
    E --> P[الحضور والإجازات والرواتب الأصلية]
    H[التقويم والنسخ السابقة محفوظة] --> P
```

المسار الحرج هو حفظ تعديل جماعي مع صون التاريخ وتزامن تغييرات الموظفين. عدد 200 مرشح حد خلفي مثبت؛ 10 مديرين و3 كتابات متزامنة و10,000 نسخة تاريخية للشركة افتراضات تخطيط، وليست سعة إنتاج مقاسة.

## خطة المراجعة واستقلالها

طُبقت مهارة `alpha-delivery-team` ومراجع الأدوار والاحتياط، مع مراجعة أمان موجهة لحدود RPC وORM؛ لا تتوافر إرشادات Odoo خاصة ضمن مراجع مهارة الأمان. لا حاجة لاعتماد جديد أو توسيع الفريق؛ الوكلاء المستقلون الحاليون يغطون التنفيذ والاختبار والمراجعة ضمن سعة الجلسة.

| المسؤولية | العمق والدليل |
|---|---|
| معماري الخريطة، رقيب الجودة، مبسط البناء | مراجعة مستقلة لجميع مسارات Calendar/Version/Wizard المتغيرة، مقابل خطة G0–G3 ومصدر Odoo المثبت. إعادة استخدام المعالج والنسخ الأصلية هو المسار المباشر. |
| حارس البيانات والحقيقة الحسابية | مراجعة عميقة للنسخ الثابتة، تواريخ النفاذ، رفض تعارضات الحضور والإجازة والرواتب، الذرية، قفل الصفوف ونسخ الرواتب دون فقد تغيير متزامن. |
| حارس الأمان والعقود والروابط | ACL المدير وقواعد الشركة، التحقق الخادمي، رفض تزوير metadata والسياق، SQL بمعاملات، وسياق token داخلي لا يمكن تزوير هويته عبر RPC. لا تكامل أو dependency جديد. |
| مختبر الرحلات ومحقق القبول | قراءة كود الاختبارات ومخرجاتها المستقلة؛ الواجهة الفعلية لدى قائد البناء وسيُراجع دليلها قبل الإطلاق. |
| مهندس السعة وأمين الدليل | تدقيق JSON والعدد والحالات السلبية وقياس 50 موظفاً وتجارب PostgreSQL الفعلية. |
| حارس المرشح وأمين التشغيل والاستلام | مراجعة freeze/publish: أساس WS3، حصر الملفات، hash المصدر والأرشيف، نسخة متماسكة بعد إيقاف MAIN، مقارنة الأعمدة والصفوف القديمة، ثم runtime ومنافذ mount للمرشح. التنفيذ النهائي لم يتم بعد. |

## نتائج المراجعة

| المعرف | الخطورة | النتيجة والأثر | الحالة |
|---|---|---|---|
| WS4-R1 | P1 أثناء البناء | تغيير `hr.version.active` كان يتجاوز قفل العضوية رغم تأثيره في اختيار النسخة. أضيف إلى مسار القفل وفُحص سباق أرشفة فعلي. | مغلق بالكود والاختبار |
| WS4-R2 | P1 أثناء البناء | قفل الرواتب الاستشاري وحده لا يُبطل snapshot قديمة قبل نسخ الأجر. أصبحت كل Version.write غير فارغة تلمس صف الموظف؛ فحص السباق يثبت رفض snapshot القديمة ونسخ الأجر المعتمد في الطلب الجديد. | مغلق بالكود والاختبار |
| WS4-R3 | ملاحظة نطاق | إدارة نسخ Odoo الأصلية تسمح بأرشفة/حذف نسخة أحدث أو استعادة نسخة تاريخية؛ قد يعيد ذلك اختيار التقويم السابق. هذا سلوك إدارة تاريخ قائم، وليس تجاوزاً لذرية تعديل القالب. إضافة قيد على تفعيل نسخة قديمة وحده لا تمنع حذف النسخة الأحدث وتضر استخدام التاريخ. | لا مانع؛ تبقى قواعد التاريخ الأصلية |
| WS4-R4 | مانع دليل | لا هوية frozen artifact ولا مراجعة دليل UI نهائي عند كتابة هذه المرحلة. | مفتوح حتى إلحاق الدليل |

لا علاقة استنتاجية بين الجداول المتشابهة بالاسم أو الساعات: التحديث يقتصر على الموظفين النشطين المرتبطين بمعرّف التقويم الأصلي في تاريخ النفاذ. النسخ المستقلة، حتى إن لم تُعدل أوقاتها، تبقى مستقلة. المرشحون التاريخيون وغير النشطين يدخلون القفل والبصمة فقط. الجداول السابقة تبقى نشطة للوصول التاريخي وتختفي من قائمة القوالب.

## سلطة الحساب وحدود القبول

الدقائق الصحيحة وDecimal في الخلفية مصدر مدد الفترات والمجاميع والتنسيق HH:MM؛ الواجهة تجمع الإدخال وتعرض الناتج. حقول Odoo العشرية تظل محول التكامل السابق. المقارنة مع تقسيم الراتب الأصلي تفرض أول الشهر إذا تغير التقسيم؛ لا حركة رواتب أو قيد محاسبي ينشئه تعديل القالب.

العملية كلها داخل savepoint ومعاملة واحدة؛ لا تغيير موظف قبل انتهاء كل فحوصه وفحوص زملائه. قفل الموظفين يسبق لمس التقويم، ومشارِكو تغييرات العضوية يلمسون التقويم أيضاً. هذا يمنع تجاهل موظف أُضيف في snapshot متزامنة. المصدر السابق وتواريخه وصفوف حضوره لا تعدل.

لم تشمل هذه المراجعة اختبار اختراق شامل، اعتماد سياسات الرواتب القديمة، أو شهادة حمل للإنتاج. مراجعة MAIN النهائية تتطلب نسخة احتياطية متماسكة حديثة، مساواة الإسقاط القديم للصفوف والأعمدة، وصحة خدمة المرشح بعد التحديث. لا تغيير لأوقات جداول العمل التجارية أثناء تثبيت الميزة.

## سجل الدليل

- DR1: قراءة مهارة التسليم ومراجعها، مراجعة فرق WS3 والملفات الأربعة، نموذج الأمان والخريطة القائمة، كود fixtures وآثار QA؛ قراءات فقط.
- DR2: تحقق مستقل آلياً من 61 و72 و107 فحصاً دون إخفاق، وقراءة تفاصيل السباقات والتوقيت؛ لا كتابة بيانات أو تشغيل حمل.
- DR3: إعداد هذا الحكم المرحلي قبل التثبيت. يُلحق حارس المرشح قرار PREDEPLOY بعد مطابقة المرشح ودليل الواجهة؛ لا تُحذف نتائج المراجعة السابقة.
- DR4: فحص مستقل لـAST نموذج Python وliteral manifest وXML الواجهة نجح عبر Python3 الموجود في حاوية Odoo؛ أُرسلت نصوص المصدر المحلي للفحص فقط. محاولة Python المحلية الأولى لم تعمل لأن الاسم مرتبط باختصار متجر Windows، ولم تثبت شيئاً. طابقت hash ملفات الاختبار ومخرجات WS4 ما سجله منفذ QA.

## DR5 — القرار النهائي قبل النشر

**GO / PREDEPLOY-GO** للمرشح `a6401283d15b09abb74b6ebb4ed560097de5242d`. هذا القرار اللاحق يغلق مانع الدليل WS4-R4 ويتجاوز الحكم المرحلي أعلاه. لا عيوب P0/P1 مفتوحة ضمن النطاق.

تحقق المراجع مستقلاً من نظافة مستودع المرشح ومطابقة HEAD، ومن SHA256 لكل ملف مصدر وعددها **1104**، ومن محتوى كل مدخل بالأرشيف وعددها **1104**. لا فرق غير الملفات الأربعة المعتمدة داخل addon الجدول ولا ملفات محذوفة مقارنة بأساس WS3. SHA256 الأرشيف: `d2073244ccba68f048dad2a1a8ca18d0f86550969dba1d130aeb3c050b664d87`. دليل الفحص الآلي محفوظ في `independent-artifact-check.json`؛ أُصلح تمثيل عدد الملفات في مخرج PowerShell من مصفوفة أعداد إلى العدد 1104، دون إعادة تفسير نتائج hash.

طابقت بصمات model/XML/PO في دليل الواجهة المصدر المجمد. رُوجع `ws4-ui.json` (10 فحوص ناجحة) و`ws4-ui-persisted.json`: حفظ فعلي من واجهة QA العربية غيّر متوسط اليوم 10:30 إلى 11:00 بدءاً من 2026-09-10 لموظفين اثنين، مع صون الأجر والجدول السابق. الدليل يشمل الإنجليزية والعربية على سطح المكتب والجوال بعرض 390، عدم تجاوز العرض، منتقي الدقائق، فتح التاريخ والنسخة الأحدث، ورفض الخطأ برسالة عربية. المعاينة البصرية أجراها قائد البناء في المتصفح؛ الصورة ظهرت داخل المحادثة ولم تُحفظ PNG، ولم يدّع هذا المراجع أنه شاهدها بنفسه. رُبط ذلك بقراءة native مستقلة للحالة المحفوظة، ومراجعة XML والترجمة وحدود الواجهة، بما يكفي لهذه الإضافة الموضعية.

تصحيح الأرقام في التواريخ يعيد استخدام `baseer_latin_date` من `baseer_report_layout`، وهو اعتماد انتقالي قائم عبر `baseer_payroll`، دون مكتبة جديدة. وثيقة فرق الخريطة `docs/architecture/registry/WS4-SCHEDULE-EDIT.md` متاحة. G4 وG7 وG8 كمرشح قبل النشر **معتمدة**، وG5/G6 تبقيان معتمدتين.

رُوجع سجل تنظيف QA النهائي: المحاولة الأولى رُفضت بسبب حماية ارتباط التاريخ فتراجعت؛ المحاولة المصححة حذفت نسخ fixture صراحة ثم التقويمين، وانتهت `UI_FIXTURE_REMOVED`. لا تغيير مصدر نجم عن التنظيف. تبقى خطوة النشر المصرح بها مسؤولة عن النسخة الاحتياطية الحديثة، ثبات الصفوف القديمة، وصحة runtime للمرشح؛ تلك أدلة ما بعد التنفيذ وليست عيوباً مفتوحة في المرشح.

## DR6 — تحقق النشر وفجوة مدخل القائمة الأصلية

وصل دليل نشر المرشح a6401283: `main-preservation.json` يثبت مساواة الأعمدة والصفوف القديمة في 250 جدولاً محمياً، و`runtime.json` يثبت HTTP 200 وتشغيل المصدر المجمد. لا تغيير لساعات الجداول التجارية أثناء النشر. أبلغ قائد البناء عن فتح نموذج MAIN الفعلي لجدول 12 من action 99، ومعاينة 4 موظفين وتاريخ بأرقام غربية، ثم الإلغاء دون حفظ.

ظهر فرق موضعي بين قائمة القوالب الخاصة وقائمة التقويمات الأصلية التي يستخدمها المستخدم: action 823 يستبعد المصدر السابق عبر baseer_is_template، بينما action 99 قد يعرض المصدر القديم والبديل بالاسم نفسه لأن المصدر القديم يبقى active لصون وصول التاريخ. هذه فجوة واجهة **P2 / WS4-R5**، وليست فساد بيانات أو خللاً في ذرية النسخ. رُجحت معالجة XML محدودة للـaction الأصلي: المحافظة على domain الحالي وإضافة `baseer_superseded_by_id = False`، دون فلتر عام للنموذج أو أرشفة المصدر أو منع فتحه من سجل الموظف. أعيد فتح G4/G7 لهذه المعالجة؛ يلزم تحقق QA لمسار القائمة الأصلية بعد تعديل fixture، ثم تثبيت مرشح المتابعة ومراجعته. يظل أثر نشر WS4 الأساسي صحيحاً وفق دليل حفظ البيانات، ويُوثق إغلاق فجوة القائمة في ملحق لاحق.

## DR7 — اعتماد تصميم معالجة القائمة مع مراعاة إزالة addon

قُبل اقتراح قائد البناء الأقصر والأصح بدلاً من domain دائم على action الأصلي: إضافة فلتر بحث مسمى «الجداول الحالية» في امتداد `resource.view_resource_calendar_search`، بمسند استبعاد التقويم المستبدل، وتفعيله افتراضياً في context action 99 مع المحافظة على domain وسياق الشركة الحاليين. يوضع الفلتر في مجموعة مستقلة باستخدام separator حتى يجتمع مع فلاتر الشركة بمنطق AND. يستطيع المستخدم إزالة الفلتر لرؤية التاريخ عن قصد.

السبب: عند إزالة addon يُحذف امتداد search view، فلا يبقى domain في action أصلي يشير إلى حقل محذوف. قيمة search_default غير المرتبطة بفلتر تصبح بلا أثر؛ لذلك لا حاجة إلى uninstall hook أو تغيير النموذج. إصدار المتابعة `19.0.1.1.1` محصور في XML والترجمة وmanifest. **G4 design معتمد** لهذا التعديل قبل التنفيذ؛ قبول G7 النهائي ينتظر إثبات القائمة الافتراضية، إزالة الفلتر للوصول للتاريخ، استمرار فلتر الشركة، ومطابقة مرشح المتابعة.

## DR8 — إغلاق فجوة القائمة في مرشح WS4A

اعتمد المراجع PREDEPLOY-GO للمتابعة `2b555de2dc26349098dd1ab741d26e0eb260c334` بعد فحص مستقل لجميع ملفاتها ومداخل الأرشيف (1104)، وحصر الفرق في XML/PO/manifest دون تغيير backend، ومراجعة الفحوص السبعة للقائمة الأصلية وإتاحة التاريخ وقيد الشركة. قرار التفاصيل في `../2026-09-09-current-schedules/PREDEPLOY-GO.md`. WS4-R5 مغلق في المرشح وG4/G7/G8 معتمدة؛ إثبات تنفيذ المتابعة على MAIN يضاف إلى حزمة المتابعة بعد النشر.
