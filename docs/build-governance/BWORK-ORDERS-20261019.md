### فجوات ينبغي حسمها قبل بناء قسم الطلبات

- **جلسة الطلبات فقط:** الخادم يسمح بالمستخدم المخول للطلبات دونchat_view، وBWork الحالي يرفضه. يلزم حدجلسة مشترك موثق مع بقاء حارس المحادثة كما هو، لا إعطاء المستخدم حقchat_view تلقائيًا أو تعديلChatEngine داخليًا بلا تفويض.
- **سجل الاستلام المكتمل:** DTO الحالي لا يقدم actual_price/actual_total في التفاصيل بعد الإتمام؛ confirm يعيد actual_total والقائمة تستبعدpurchased. شاشة سجل استلام مكتمل مطلب إضافي بعقد جديد، لا ميزة نفترض وجودها أو نخترع قيمها.
- **بدون محادثة:** الإنشاء بلاroom صالح، لكن مشاركة الفعلي لاحقًا تتطلب الغرفة الأصلية. يُحفظ سلوك القديم ضمن النقل؛ أي ربط غرفة بعد الإرسال ميزة جديدة تحتاج عقدًا.
- **مستخدم الاستلام فقط:** لا يُحجب بسبب options الشركة الذي يحتاج الإنشاء أو بسبب تحميل قائمة مندوبين غير لازمة؛ لا ربط مصطنع لصلاحية الإنشاء والاستلام.
- **السعر والنطاق:** عرض السعر تقديري لا حجز؛ requested_total ليسactual_total، والسعر الحالي ليس التاريخي. scope=all يعني قناةBChat فقط والشركات المصرح بها، لا جميع قنوات المشتريات.
- **دليل البيئة:** وجود الاختبارات ومطابقة المصدر لا يثبتان نشره أو schema أو صلاحية المستخدم على الهدف. لا تشغيل بيانات حقيقية أو تحميل كتالوج خادمي ضمن الدراسة، لأن هذا الأخير قد يكتب خيارات افتراضية.
