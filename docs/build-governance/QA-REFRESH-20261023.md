## العقد والخريطة — G0–G3 قيد المراجعة

تفويض المالك: إنشاء QA من آخر LIVE فعلي، حفظ القديمة وتجارب الفوترة قبل الاستبدال، تعطيل الاتصالات الخارجية والفحص ثم الاستبدال. لا تفعيل Phase2 أو إرسال API/OTP ضمن هذه العملية. المصدر التشغيلي يبدأ من فرع codex/qa-refresh-20261023 من main1f5e9fcf؛ لا كتابة على قاعدة LIVE أو ترقية موديولاتها أو تعديل ملفات إصدارها.

الخريطة المعاد استخدامها: LIVE مصدر فعلي DB+filestore+custom/thirdparty/image → زوج snapshot محمي → PG وOdoo volume جديدان منفصلان → مطابقة قاعدة/مرفقات → neutralization وعزل الشبكة → QA candidate محلي → تحويل QA الحالي بعد قبول مستقل. QA القديمة وكل مواردZATCA تبقى محفوظة. لا إعادة رسم أو اختبارات حسابات أو حمل غير متغيرة.

G0: القبول يثبت آخر source marker الفعلي والصورة وبصمات الموديولات؛ نسخة QA القديمة وكل قواعد PG فيها، المصدر/config والـfilestore محفوظة root0700 وhash. يشمل zatca_phase2_qa_test_20261004 داخل QA PG، وكل volumes وملفات ZATCA المستقلة ومنها SimulationV2 والـPG المتوقف. لا حذف/استبدال volumes القديمة. صلاحيات المستخدم والشركات والحركات محفوظة في النسخة الجديدة؛ مفاتيح الخدمة والجلسات والاتصالات التشغيلية لا تنقل إلى التشغيل الجديد.

G1: مالك واحد وطلبات فحص قليلة، قاعدة LIVE المرصودة نحو265MB، المساحة الحرة36GB. الجرد الفعلي والأحجام يحددان قبول المساحة قبل النسخ؛ لا اختبار حمل. غرض تجربة الاستعادة الوحيدة هو إثبات زوج النسخة الجديدة ومرجع القديمة، لا إعادة فحص التطبيق. LIVE يظل يعمل؛ QA فقط يجوز إيقافها للحفظ/التحويل. الرجوع إلى config/source/volumes القديمة محفوظ ومحدد.

G2: لا تغيير للعقود أو الحسابات أو الأسماء أو VAT. pg_dump snapshot ثم نسخ filestore content-addressed، والتحقق بعد الاستعادة من كل مرفق مشار إليه بالحجم وSHA1؛ أي ملف ناقص يوقف القبول قبل HTTP والتحويل، فلا تدعى consistency من وقت نسخ فقط. تثبيت source marker قبل/بعد النسخ؛ تغير المصدر يوقف العملية. البصمات المالية والعضويات والموديولات والمرفقات تقاس على القاعدة المستعادة من نفس snapshot قبل neutralization، وتحفظ مقارنة بعده exact مع استثناء تغييرات العزل المحددة فقط. مصدر LIVE لا يقارن بعداد متحرك في وقت لاحق.

العزل قبل أول Odoo process: PG وشبكة داخلية منفصلان؛ منفذ HTTP loopback فقط. منع outbound من namespace Odoo وhost/other containers مع السماح لعنوان PG المحدد والرد على ingress القائم فقط؛ اختبار فعلي TCP مقابل host/Internet/LIVE PG مع deny قبل HTTP. لا mount لشهادة FCM أو مفاتيح LIVE؛ runtime/config جديدان بأسرار QA مستقلة. native Odoo neutralize على النسخة فقط مع crons=0، وتعطيل mail/payment/print agents/jobs/Google/WhatsApp/APIs المخصصة وفق جرد schema، وتغيير tokens والجلسات ضمن قائمة محددة. لا نجاح بناء على تعطيلcron وحده. قبول Arabic/English login وقراءة التقارير/الشركات وPOS metadata دون دفع/طباعة أو رسائل.

G3: نفس صور Odoo/PostgreSQL الحالية والمكتبات المدمجة/Python stdlib وDocker/pg_dump/restore وGit/OpenSSH القائمة، لا اعتماد جديد ولا UI جديد. مسار refresh قائم غير موجود؛ تعديل عمليات مستقل في Git ثم PR/CI ناجحة، GitHubActions بطلب موقع ببيئةqa، وغلافroot محمي ثابت من revisionالمراجع. لا arbitrary command ولا production workflow. Bootstrap المحدود يثبت الغلاف من المصدر المجمد ويحفظ سابقه؛ طلبActions يحدد source LIVE وQAالمتوقعين، يتوقف عند تغيرهما. المرحلتان prepare/switch واضحتان مع intent/receipt دائمين وقفل QA/poller؛ لا إعادة snapshot/تشغيل غامضة عند الفشل.

G4: لا تصميم/لغة/واجهة جديدة؛ تحقق الاستخدام على الواجهة الحالية فقط. G6: لا تغيير محرك أو سعة؛ زمن الاستعادة/جاهزيةHTTP وحجم القرص دليل تشغيلي محدود فقط. G8: مراجعة مستقلة قبل التحويل النهائي وبنفس الأدلة، ثم بعده.

حد العزل المعتمد الأحدث: مكونات QA داخل شبكتها تتواصل مع بعضها، ويمنع الخروج إلى الإنترنت والمضيف وPG اللايف بجدار الحماية الخاص بالشبكة. شبكة Docker ذات Internal=true منعت نشر منفذ HTTP المحلي أيضًا؛ أجيز استبدال شبكة المرشح وحدها بجسر عادي بنفس الاسم والعناوين مع تطبيق الحماية قبل تشغيله. لا يشمل الطلب عزل كل حاوية عن بقية مكونات QA الموثوقة.
