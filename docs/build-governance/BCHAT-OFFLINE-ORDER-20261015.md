# BCH-OO-20261015 — BChat: سرعة التطبيق والعمل دون اتصال للمحادثات والمهام

**النطاق:** QA فقط. لا APK للتسليم ولا نشر QA أو Live بهذا العقد. الأساس التقني `49d6ef92` (BChat Android v52)، وفرع العمل `codex/bchat-offline-order-qa-20261015`.

## G0 — عقد المنتج (بانتظار مراجعة مستقلة)

- **المستخدم والهدف:** موظف BChat سبق له الدخول بنجاح؛ يفتح سريعاً آخر محادثاته ورسائله ومهامه المحفوظة عند انقطاع الشبكة، من دون ادعاء أن البيانات أحدث من الخادم.
- **الدخول دون اتصال:** لا دخول أول مرة، ولا كلمة مرور محفوظة. يسمح فقط بعرض النسخة المحلية لحساب سبق التحقق منه على نفس الأصل/قاعدة أودو/المستخدم خلال 24 ساعة من آخر تحقق موثوق؛ بعدها يلزم اتصال. تسجيل الخروج يمسح نسخة الحساب. أما سحب الصلاحية أو الشركة من أودو فلا يمكن معرفته أثناء الانقطاع، ويطهر عند أول bootstrap موثوق لاحقاً.
- **المسموح دون اتصال:** قراءة قائمة الغرف والرسائل النصية المحفوظة، وقراءة المهام التي تم التحقق منها سابقاً. الصور والوسائط تبقى متصلة في هذه الشريحة حتى لا تُضاف ذاكرة وسائط غير محدودة أو تُدّعى خصوصية لا نتحقق منها. تظهر بوضوح «نسخة محفوظة» ووقت آخر مزامنة؛ لا تظهر حالة حديثة على أنها مؤكدة.
- **الممنوع دون اتصال:** إنشاء أو تعديل أو إكمال مهمة، إرسال رسالة أو مرفق، إنشاء طلب أو عرضه من cache مستقل، تأكيد استلام، تغيير كمية أو سعر فعلي، حركة مخزون، فاتورة، دفعة، عهدة، تحويل أو تسوية. تعرض الواجهة «يلزم الاتصال» من دون أثر جانبي.
- **عند عودة الاتصال:** تحقق هوية وجلسة وصلاحية المستخدم أولاً، ثم يجلب room/task snapshot حديثاً ويستبدل النسخة المحلية ذرياً. لا مزامنة كتابة مؤجلة في هذه الشريحة.
- **الأحجام والوحدات:** لا تغيير في مسار المنيو أو الطلبات في هذه الشريحة. يبقى `baseer.procurement.purchase.option` (`option_id`) هو المصدر الصحيح إذا فُتح تحسين منيو لاحقاً.
- **خارج النطاق:** أي كتابة offline أو طابور طلبات، تغيير سياسات أودو المالية أو المخزون، مزامنة خلفية غير مرئية، أو نشر Live.
- **عداد غير المقروء:** الرقم المعروض في قائمة الغرف هو عدد إيصالات الرسائل الواردة فقط التي ما زال `read_at` فيها فارغاً في الخادم؛ لا يدخل فيه ما أرسله المستخدم ولا رسائل عضوية سابقة. عند رؤية فقاعة رسالة فعلياً يرسل التطبيق إيصال قراءة، ولا يخفي الشعار إلا بعد رد الخادم الناجح الذي يحمل العدد الموثق الجديد للغرفة. لا يُستنتج عداد جديد من cache عند offline؛ يظهر آخر snapshot بوصفه محفوظاً ولا تُجرى إيصالات قراءة أو كتابة محلية.

## G1 — السعة والاستعادة (بانتظار مراجعة مستقلة)

- الأساس القائم: 35 مستخدماً و10 متزامنين. تُحد كل نسخة محلية حسب الحساب والشركة، ولا يُستخدم تاريخ المحادثات كمنيو.
- المهام المحفوظة: آخر صفحة موثوقة واحدة فقط (حد أودو: 30 مهمة) لكل حساب/غرفة/مرشح حالة/**مجموعة الشركات المصرح بها**، بحد إجمالي 120 مهمة و2 MiB. الاستجابة الحالية مختلطة الشركات؛ يحمل كل سجل `company_id` وتزال سجلات الشركة المسحوبة عند أول bootstrap موثوق، ولا يملأ العميل الفراغ بصفحة قديمة. لا جلب متعدد الصفحات في الخلفية، لأن API الحالي لا يقدم snapshot token؛ لذلك لا ندّعي أن تاريخاً كاملاً متسقاً محفوظ محلياً.
- الهدف: إظهار نسخة cache خلال 400ms على جهاز متوسط إن كانت موجودة؛ هذا هدف قياس محلي، لا ضمان شبكة. فشل schema أو امتلاء التخزين لا يكسر الدخول؛ يعرض رسالة واضحة ويترك الخادم مصدراً للحقيقة.
- التراجع: schema SQLite إضافي وغير مدمر وfeature flag محلي؛ إيقاف المسار لا يغير بيانات الخادم ولا يرسل شيئاً تلقائياً.

## G2 — الملكية والعقود والأمان (بانتظار مراجعة مستقلة)

- أودو يملك الهوية، الجلسة، الصلاحيات، الشركات، الغرف والرسائل والمهام. Android يملك عرضاً محلياً مقيداً بالحساب للقراءة فقط.
- يجب أن تكون كل البيانات المحلية مقيّدة بـ`origin + database + user + company`، وتُمحى عند logout أو عند bootstrap موثوق يثبت سحب حق/شركة. لا يجوز لنسخة شركة أو مستخدم أن تظهر لآخر. أهلية الدخول البارد مستقلة عن تبويب المحادثات: يكفي `chatView` مع cache غرف أو `taskView` مع cache مهام؛ ولا يكشف أحد المسارين بيانات الآخر.
- لا يضاف طابور كتابة offline ولا إعادة إرسال تلقائية للمهام أو الطلبات في هذه الشريحة. عمليات v52 المعلّقة الموجودة تبقى كما هي ولا يحذفها مسار القراءة الجديد؛ وأي ضغط كتابة جديد بلا شبكة يفشل محلياً برسالة واضحة.
- إيصال القراءة مقيد بالخادم إلى الغرفة والشركة وعضوية المستخدم النشطة وعصر العضوية والرسالة الواردة فقط، وهو idempotent. يعيد الخادم `unread_count` و`last_message_id` محسوبين بعد القفل والتحديث؛ Android يقبلهما فقط لإيصال `read` مؤكد ولعضوية الغرفة المطابقة. يحمل طلب ACK جيل قائمة الغرف الذي خرج معه، فلا يطبق الرد إذا استُبدلت `/rooms` أثناء الطيران — حتى لو بقيت آخر رسالة نفسها وتغيرت القراءة من جهاز آخر. وبالعكس، يحمل طلب `/rooms` جيل قراءات التطبيق؛ إن تأكدت قراءة قبله يُهمل رده ويُجلب snapshot جديد. لذلك يمكن مغادرة الغرفة قبل الرد من دون بقاء badge قديماً، ولا يستطيع أي رد قديم الكتابة فوق snapshot أحدث.
- cache المهام يستقبل فقط استجابة صفحة واحدة مرّت بمتحقق v2، ويستبدل الصفحة المطابقة محلياً دفعة واحدة بعد اكتمال parsing. فشل الجلب أو التحقق يبقي النسخة السابقة موسومة بأنها قديمة؛ ولا تدمج صفحات متعددة أو بيانات جزئية. عند bootstrap موثوق تُزال صفحات شركة/صلاحية مسحوبة.

## G3 — الطريق المباشر والتبعيات (بانتظار مراجعة مستقلة)

- لا مكتبة جديدة ولا خدمة سحابية: Java/Android SDK وSQLite الموجودة، `OdooIdentityActivity`، وطبقات BChat الحالية. لا يُعاد استخدام `ConnectedHistoryCache` لحفظ المنيو، لأنه مخصص لعضوية الغرف والرسائل.
- تُبنى طبقة `TaskOfflineCache` منفصلة ومحدودة، مع اختبارات Java للـscope، حدود الحجم، ترحيل schema، تبديل الحساب/الشركة، وفشل الشبكة/قتل العملية.
- يُصحح توافق رقم الإصدار قبل أي بناء: Gradle v52 مقابل ملفي Manifest v51.
- اختبار الخادم يبقى موجهاً لعقد المهام القائم: صلاحية أو شركة مسحوبة، ترتيب/حدود الصفحة، ومنع أي كتابة offline.

## G4 — تجربة الاستخدام (بانتظار مراجعة مستقلة)

- badge صغير ثابت يوضح «محفوظة بتاريخ…» للبيانات غير المتصلة. لا spinner دائري متكرر أو حركة انتقالية على التبديل السريع؛ أزرار الكتابة معطلة بوضوح عند offline وتشرح السبب.
- عربية/إنجليزية وRTL/LTR من الموارد نفسها، 320/360/800dp، تكبير خط 1.5× وأهداف لمس 48dp. لا تستخدم الواجهة لوناً وحده للدلالة على offline أو conflict.
