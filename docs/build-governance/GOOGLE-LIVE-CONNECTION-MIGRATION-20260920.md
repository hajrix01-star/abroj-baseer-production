# GINT-LIVE-CONN-1 — نقل اتصالات Google إلى الحي

## عقد البناء والترحيل

**الهدف:** تفعيل الاتصال الفعلي في الحي لإضافتي Google Business وGoogle Ads
من دون إعادة تفويض المستخدم، عندما تكون رموز المصدر القديمة صالحة.

**النطاق المعتمد:** اتصالا `ARZ LOUNGE` و`المعلم الشامي` الفعّالان فقط، لكل
من Google Business وGoogle Ads. لا تُنقل حالات `attention_required` ولا
اتصالات NOORIX غير المطابقة لشركة أودو محددة.

**خارج النطاق:** لا حذف للمصدر القديم، ولا تفعيل كتابة ردود Google Business،
ولا تغيير للأرقام المحاسبية أو المبيعات، ولا نقل سر إلى Git أو سجل أو متصفح.

**معايير القبول:** اتصال واحد فقط لكل علاقة مصدر/شركة/خدمة، رمز يبقى في
الذاكرة أثناء النقل ويخزن في الحي مشفراً بمفتاح حي مستقل، إعدادات عميل Google
في مخزن خادمي محمي فقط، وقراءة Google محدودة تثبت هوية الحساب/الموقع.

## البوابات

| البوابة | الحالة | الدليل |
|---|---|---|
| G0 | معتمدة | تفويض المالك الصريح، النطاق والشركات أعلاه |
| G1 | معتمدة | أربع وصلات فعالة كحد أقصى؛ عملية لمرة واحدة وقراءة محدودة |
| G2 | معتمدة مشروطاً | envelope هجين بالمفتاح العام للحي، AAD ملزم، allowlist، قفل/معاملة/receipt منقح |
| G3 | معتمدة | لا اعتماد جديد؛ Python/Node/OpenSSL وOdoo الحالية فقط |
| G4 | غير منطبقة | لا تغيير واجهة في هذه الموجة |
| G5 | قيد المراجعة | استيراد آمن ثم قراءة محدودة لكل خدمة/شركة |
| G8 | غير مبدوءة | مراجعة تسليم مستقلة قبل اعتماد الحي جاهزاً |

## المسار المباشر والأمان

يفك المصدر الرمز داخل حاويته فقط، ويغلفه بـAES-GCM عابر؛ ثم يغلف مفتاح AES
بالمفتاح العام للحي. لا ينتقل مفتاح خاص أو مشترك إلى المصدر. يربط AAD الموثق
بالبيئة production والخدمة ومعرف الاتصال القديم وشركة أودو والحساب والموقع أو
العميل المتوقع. يرفض المستورد اختلافاً واحداً، أو صفاً خارج allowlist، أو صفاً
active، ثم ينشئ/يقفل صف pending فريد ويعيد تشفير رمز التحديث بمفتاح الحي.
تمر الرسالة المغلفة عبر stdin ولا تكتب إلى القرص. تسجل النتيجة برمز حالة
وreceipt غير عكسي فقط.

يبقى المصدر الكاتب الوحيد وOdoo read-only؛ `writer_enabled=false` ولا يبدأ
outbox أو worker كتابة في هذه الموجة. يفحص اختبار القراءة الهوية الخارجية:
Customer ID في Ads وAccount/Location في Business.

## ملف السعة والاستمرارية

- الرحلة الحرجة: إنشاء اتصال ثم قراءة واحدة مقيدة لكل خدمة/شركة.
- الحجم الحالي: أربع وصلات فعالة؛ لا تشغيل متزامن ولا دفعات تاريخية.
- التزامن: قفل صف فريد ومعاملة واحدة لكل اتصال؛ إعادة التشغيل لا تنشئ وصلة ثانية.
- الاستعادة: تعطيل الصفوف المستوردة أو حذفها قبل القراءة فقط؛ لا تمس بيانات
  أعمال أو المصدر القديم.

## دفتر العمليات الحي

| المعرّف | المرحلة | النوع | النتيجة/الدليل |
|---|---|---|---|
| L1 | G0 | قراءة | إضافات الحي مثبتة لكن جداول الاتصال والحقائق صفرية |
| L2 | G0/G1 | قراءة | أربع وصلات source active: ARZ والمعلم الشامي، Ads وBusiness؛ المعرّفات خُرطت للشركتين 1 و2 |
| L3 | G2 | قرار | استبعاد Ads attention-required وNOORIX؛ اعتماد allowlist وAAD وقفل replay |
| L4 | G2 | قراءة | مفاتيح المصدر موجودة بالاسم فقط؛ الحي لا يملك إعدادات Google Baseer بعد |
| L5 | G2 | مراجعة مستقلة | حارس الأمان ألزم المفتاح العام، AAD، منع replay، تحقق الهوية وسياسة الذاكرة/الرجوع |
| L6 | G5 | اختبار | عقد envelope: اختبار Node ناجح؛ اختبار decrypt/binding Python ناجح (2/2) |
