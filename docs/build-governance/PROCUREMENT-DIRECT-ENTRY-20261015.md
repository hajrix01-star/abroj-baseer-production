# PROCUREMENT-DIRECT-ENTRY — عقد تعديل محدود

**التاريخ:** 2026-10-15
**النطاق:** مصدر واجهة دفعة شراء ومراجعة ترتيب القوائم؛ QA فقط عند اكتمال المرشح. لا تغيير بيانات أو قيد أو دفعة أو اعتماد.

## G0 — الهدف والحدود

- عند إنشاء دفعة إدخال مشتريات بلا طلب استلام مرتبط، تعرض القائمة والنموذج مصدرها: `Direct entry — <creator>` بدلاً من نسبة عامة لدور «المحاسب».
- يستعمل الاسم سجل تدقيق أودو الأصلي `create_uid`، ولا ينشئ طريقة دفع أو حالة سداد أو حركة محاسبية.
- الدفعات المرتبطة بطلب استلام تبقى تعرض مسار الطلب الأصلي ولا تستبدل بهوية المستخدم.
- العربية والإنجليزية تأتيان من ترجمة أودو، والاسم نفسه يظل اسم مستخدم أودو المعتمد.

## G1 — السعة والاستمرارية

الحجم الشخصي الحالي محدود، والحقل المعروض هو علاقة تدقيق موجودة على كل سجل؛ لا جدول أو فهرس أو استعلام تجميعي أو عملية خلفية جديدة. الهدف: قراءة قائمة الدفعات ضمن زمن القائمة الحالي.

## G2 — العقد والرقابة

- مصدر الحقيقة للمنشئ هو `create_uid` غير القابل للتحرير من المستخدمين العاديين.
- تسمية المصدر حقل محسوب غير مخزن للعرض فقط: مسار الطلب إن وجد، وإلا إدخال مباشر مع منشئ السجل.
- لا يعتمد الحقل في الموافقة أو حساب الإجماليات أو تحديد طريقة السداد؛ تبقى هذه في دورة الدفعة الخلفية القائمة.
- حالات الاختبار: دفعة مرتبطة بطلب، دفعة مباشرة، اختلاف لغة البيئة، وعدم تغير `create_uid` أو الأثر المالي.

## G3 — المسار المباشر

إعادة استخدام ORM والترجمة وواجهة قائمة/نموذج Odoo القائمة، بلا مكتبة أو اعتماد أو schema جديد. البديل المرفوض: حقل مستخدم قابل للتحرير؛ لأنه يخالف سجل التدقيق ويتيح نسبًا غير صحيحة.

## G4 — العرض

عمود واحد «المصدر / Source» بعرض محدود في القائمة، وحقل قراءة فقط في النموذج. يلتف النص على المساحة الضيقة ولا يعتمد على لون أو hover.
