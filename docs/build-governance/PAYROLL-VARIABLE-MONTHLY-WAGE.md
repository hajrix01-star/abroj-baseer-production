# Payroll monthly wage input

Reference BP-VW1 · baseline `35de6a7d4` · owner `baseer_payroll` · architectural (payroll and schema).

| Gate | Accepted design and evidence |
| --- | --- |
| G0 | Owner confirmed the entered amount is the entire gross for the period, with no fixed wage. Draft creation loads eligible staff. A payroll manager enters one amount per variable employee; missing amounts block approval. Accounting approval posts the existing expense, payable and deductions. The posted slip is immutable and reviewed corrections remain the repair path. Doha activation is operational configuration, not a hard-coded employee name. Quality and accounting reviews confirmed this path. |
| G1 | Intended use: three manually entered rows per monthly run (36/year), one payroll operator, allow for a second concurrent editor/approver. No new searches, batch jobs, or historical backfill; retain one input with its existing slip. Use the current run and employee locking and backup/restore path. Target the same interactive response as editing a deduction; no synthetic load environment is justified by this additive row field. Quality reviewed against the existing monthly run. |
| G2 | Version opts into variable mode with zero contractual wage/allowances. The managed draft slip owns a copy-disabled gross input; server validates positive cents for approval and uses the entire input once, without contract or unpaid-day proration. Missing/cleared input cannot post. Fixed rules, deduction validation, native reconciliation and EOS wage authority stay separate. Rows with manual input survive refresh and cannot be reassigned. Accounting review confirmed the balance and zero-gross boundary. |
| G3 | Direct route: reuse Odoo ORM monetary fields, existing decimal helpers, record permissions, payroll structure and native widgets. No new dependency, ledger, deployment script, or service. Focus verification on mixed payroll, refreshed/preserved input, isolation, native posting, and existing responsive UI. |
| G4 | Use the existing payroll desktop list and mobile employee form. The Arabic and English labels use Odoo translations; preserve native monetary and RTL/LTR rendering. |
