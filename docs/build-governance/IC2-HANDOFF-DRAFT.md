# IC2 — Unified source lifecycle

Release identity and deployment outcome must be filled from candidate/runtime/preservation evidence after publication. This draft is not a release claim.

The native correction addon now coordinates an eligible invoice and its dedicated manual payment as one operation. Cancellation requires a reason and explicit acknowledgement that the payment was recorded in error. It preserves the original records and cancels their bookkeeping effect through native Odoo methods; it does not issue a bank refund or erase history. Persistent invoice/payment links and native reconciliation evidence are both resolved, including an already-cancelled invoice whose dedicated payment remains posted. Ambiguous/shared, bank-statement matched, locked and protected source states are rejected before mutation.

Each approved purchase-batch row is the operation boundary. Its invoice/payment are cancelled together; the row is marked cancelled with actor/time/reason, retained with its original amount and links, and excluded from active totals. Printed summaries mark cancelled rows with zero active amount and retain the original amount in their description. Whole-batch cancellation is not implemented. Corrections retain explicit actual payment amounts rather than guessing them from invoice totals.

Approved sales summaries expose Edit / cancel operation. Editing reverses the original native sales and receipt entries, creates a replacement with the entered customer count and original payment-method amounts, and approves it inside one transaction. Cancellation reverses the same source without creating a replacement. Failure restores the whole operation. Cash, bank and platform receivable accounts continue using the existing source posting engine. The prior and replacement summaries remain linked and the common audit is immutable.

Owner access and per-accountant Allow financial operation correction remain the controlling settings. Cashiers cannot correct or cancel through this workflow. Permissions/company access are rechecked at confirmation. Native destructive entry/payment/source paths cannot bypass linked-operation protections. Payroll, loans, HR services, stock, assets and externally settled/shared cases retain their source-specific native workflows; this release does not rewrite their lifecycles.

Validation:60 focused core checks and38 summary checks, with hard commit guards/full rollback/module preservation; two actual concurrent-session cases; actual Arabic/English and480px browser journeys; read-only accounting verification of the browser mutations. Same-source competing invoice edit/cancel yields one winner; summary amount editing serializes with confirmation and the posted amount matches the final request. Bounded local fixture timings are under3seconds, not a production-scale certification. Native mobile payment cards are chosen when opening at mobile width.

MAIN deployment must preserve all372 pre-existing protected tables' original column values, security memberships, user roles and unrelated installed versions. Only reviewed additive fields/transient schema are allowed. No historical MAIN cancellation or QA fixture is copied/applied automatically. Source-only GitHub publication follows exact frozen-source verification. Remote server deployment remains outside this local-original release.

Rollback: keep the pre-release coherent database/filestore backup and saved compose files. If migration or preservation fails, MAIN remains stopped for investigation. A schema-changing rollback requires restoring the matched backup and previous IC1 frozen source together; do not downgrade only the code.
