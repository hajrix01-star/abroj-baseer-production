# SD1 — لوحة ملخصات المبيعات في لوحات البيانات

## G0: العقد والنطاق

2026-09-09. المستخدم طلب بناءً فعليًا وأكد موضع الميزة: موديول «لوحات البيانات» الرئيسي، قسم المبيعات، لوحة «ملخصات المبيعات». وأكد أن «معدل الفاتورة» يعني إجمالي المبيعات ÷ عدد العملاء المسجل في الملخصات. موافقة النشر على الأصلية والعمل بحزم قابلة للنقل قائمة من سياق المشروع؛ يلزم اختبار QA وقبول مستقل قبل النقل.

المطلوب: واجهة عربية/إنجليزية متجاوبة، اختيار فترة، مراعاة الشركة النشطة، رسم زمني للمبيعات والعملاء، خمس بطاقات للإجمالي والعملاء ومتوسط المبيعات اليومي ومتوسط العملاء اليومي ومتوسط الفاتورة. تحديث تلقائي بعد تطبيق/تغيير الفترة وتبديل الشركة، وزر تحديث؛ نتائج التحميل/الفشل/الفراغ واضحة. النقر على المصادر يفتح الملخصات المعتمدة المقابلة.

خارج النطاق: تعديل القيود أو آلية اعتماد الملخصات أو البيانات الشخصية، إنشاء بيانات تجريبية على الأصلية، الربح والتكلفة والعمولات، ربط مصادر بيع أخرى، بناء نظام BI منفصل، أو تجميع شركات/عملات في رقم واحد.

الشركة الحالية لا تحتوي عمليات وهذا مقصود؛ تعرض اللوحة حالة فارغة حقيقية. لا تُملأ بأرقام نموذجية على الأصلية.

## G1: السعة والاستمرارية

افتراض تصميم:3شركات حاليًا، نمو إلى50شركة، عشرة مشاهدين متزامنين، متوسط ملخصين في اليوم لكل شركة، تاريخ محفوظ لعشر سنوات. كل طلب يقرأ شركة واحدة وفترة≤366يومًا فقط. المخرجات≤366نقطة، وليست تحميلًا لتاريخ السنوات. هدف القياس المحلي: طلب سنة بعد الإحماء≤2ثانية، لا وعد أداء إنتاجي غير مقاس. لا cache أو queue أو مكتبة خارجية جديدة. تغيير الفترة لا يغير البيانات؛ تتجاهل الواجهة الاستجابة المتأخرة وتمنع إظهار أرقام شركة/فترة قديمة.

تستخدم فهارس الشركة والتاريخ/الحالة الحالية. يقاس سيناريو سنة في QA ببيانات اختبار معزولة وrollback، مع توثيق حجم العينة والزمن وحدود المقارنة. النسخة الحالية مجمدة ولهوية نشر ونسخ احتياطي معتمدتين؛ المرشح الجديد يضيف موديولًا مع بقاء الملفات السابقة دون تغيير.

مرجعSD1 v1، تصنيفARCHITECTURAL لامتداد عقد بيانات ERP وواجهة مشتركة. الأساس `8aff2c48f66df5925cf9dd98e9e7f11b55741f50`. يُعاد استخدام سجل `docs/architecture/registry/INDEX.md`؛ لا تغيير للسلطة المحاسبية.

    A[لوحات البيانات: المبيعات/ملخصات المبيعات] --> B[مكون عرض Owl خاص باللوحة]

إضافة مستقلة `baseer_sales_dashboard` تعتمد `baseer_pos_summary` و`spreadsheet_dashboard`. لا تعديل Odoo core/vendor أو معادلات الملخصات. سجل لوحة أصلي داخل مجموعة المبيعات مع تمييز الميزة ومحتوى spreadsheet فارغ صالح؛ امتداد Owl/XML محدود يعرض اللوحة الخاصة ويحافظ على التنقل الأصلي لبقية اللوحات. لا تُستخدم صيغ spreadsheet لحساب قيم الأعمال، ويُحجب تصدير/مشاركة spreadsheet الفارغ لهذه اللوحة.

واجهة القراءة على النموذج المالك للوحة/امتداده تتحقق من قراءة سجل اللوحة وإذن قراءة الملخصات والإغلاقات، وتفرض الشركة النشطة وسياقًا منظفًا دونsudo أو سياق نتائج مرسل من العميل. تستخدم `_aggregate_days` كما هو، دون إنشاء transient/report lines. هو مصدر الحقيقة لمفهوم اليوم المكتمل، الإغلاق الجزئي، مجموع المبيعات والعملاء والمتوسط اليومي. العرض لا يملك التجميع أو التقريب.

| القيمة | التعريف |
|---|---|
| إجمالي المبيعات | مجموع `recorded_sales` للملخصات المعتمدة، شامل الضريبة؛ يشمل الجزء المعتمد من يوم غير مكتمل. |
| العملاء المسجلون | `recorded_customers` لنفس العينة المعتمدة؛ لا يستخدم عدد أوامرPOS. |
| متوسط المبيعات اليومي | `complete_sales / operating_days` وفق helper القائم. لا مقام=غير متاح، وليس صفرًا مصطنعًا. |
| متوسط العملاء اليومي | `complete_customers / operating_days`؛ يتوقف عرضه إذا نقص إدخال العملاء في العينة المحتسبة. |
| متوسط الفاتورة | `recorded_sales / recorded_customers` من المجاميع، وفق موافقة المستخدم، مع توضيح «لكل عميل مسجل». ليس متوسط متوسطات الأيام. |
| صفر العملاء | إذا المقام صفر فغير متاح. إذا ملخص معتمد بمبيعات موجبة دون عملاء، يُعلن نقص عدد العملاء ويحجب متوسط الفاتورة بدل عرض نسبة مضللة؛ متوسط العملاء اليومي يحجب عندما تمس الحالة عينة الأيام المكتملة. |
| الخط الزمني | لكل تاريخ، المعتمد فقط؛ اليوم الجزئي مميز. المغلق/المفقود gap/null لا صفر. الصفر المعتمد قيمة حقيقية. |

تُظهر الواجهة أساس المتوسطات اليومية وعدد الأيام المكتملة/الجزئية/المغلقة/غير المدخلة. المسودات والملغى لا يزيدان المبيعات. الأرشفة لا تمحو تاريخ الملخص. الضريبة موصوفة في الواجهة؛ لا اختيار ضمني بين الصافي والإجمالي. الفترة الافتراضية بداية الشهر حتى اليوم بتوقيت الشركة المدعوم، أزرار فترات شائعة، وتاريخ مخصص؛ الخادم يفحص النطاق≤366يومًا.

تأتي القيم المالية والنسب المنسقة منPython بـDecimal ومنزلتين، وأرقام0–9 في اللغتين. تحويل القيم المرسلة إلى إحداثيات رسم فقط مسموح؛ لا حساب متوسط أو مجموع في JavaScript. العملة والشركة والتواريخ والأساس وحالاتعدم التوفر مصدرها عقد الخادم.

### SD1-03 — ملحق قبل اعتماد البوابات: تجميع زمني وتكامل مثبت

الفلاتر: `this_month` افتراضي،`last_month`،`last_30_days`،`this_year`،`last_year`،`custom` معتاريخين. الخلفية تحددالفتراتوالتجميع ولايفوضذلكلتقريبأوحسابمبيعاتبالواجهة. endpoint `spreadsheet.dashboard.get_baseer_sales_metrics(filters)` @api.readonly علىسجل اللوحةالخاصة. لا company_id مدخل؛ الشركةالنشطةوسياقهاتحددانالإذن. filtersقاموسمحدودللـpreset/date_from/date_to، ويرفضغيرالصالح.

### SD1-04 — طلب أسهم مقارنة البطاقات قبل البناء

طلب المستخدم سهم ارتفاع/انخفاض ونسبة مثل الصورة. تُحسب المقارنة فيالخلفية بـDecimal: `(current-previous)/abs(previous)*100` وتقربإلىمنزلتين. لكلبطاقة `comparison{direction,display,available,previous_display}`؛ direction=`up/down/flat/none/new`. اتجاهصاعدأخضر،هابطأحمرهادئ،ثابت/غيرمتاحمحايد،معنصوسهملايعتمدانعلىاللونفقط. لا∞: قيمةسابقة0وحاليةموجبةمنعينتينموجودتين=>`new` ونص«جديد»؛ صفرانموجودان=>0.00%. غيابالعينةأوعدمصلاحيةالمؤشر=>غيرمتاح، لاانخفاضمصطنع100%.
