# عقد نشر بصير أودو على Hostinger — 2026-09-11

## عقد البناء (G0)

- **الهدف:** نقل نسخة بصير أودو 19 المعتمدة إلى VPS خاص بالمستخدم، في مكدس Docker مستقل لا يشارك التطبيق القائم أو بياناته أو شبكته أو volumes الخاصة به.
- **النطاق:** مشروع Compose باسم `baseer-odoo-prod`، PostgreSQL وOdoo وملفات الإضافات المرشحة، مستخدم نشر بمفتاح SSH، مجلدات وvolumes وشبكات خاصة، نسخ واستعادة، وربط HTTPS بعد توفر اسم النطاق.
- **خارج النطاق:** حذف أو ترقية أو إعادة تشغيل حاويات `baseer-erp-private-online` أو أي مشروع آخر، ترحيل بيانات غير مصرح بها، كشف التطبيق على الإنترنت أو إصدار شهادة قبل تفعيل الدومين، وتغيير أي قاعدة محاسبية أو كود أعمال.
- **القبول:** لا اسم/volume/network/port مشترك مع المشاريع القائمة؛ قاعدة البيانات غير مكشوفة علنًا؛ التطبيق لا يتصل بقاعدة أو ملف تطبيق آخر؛ يمكن إيقاف أو إزالة مشروع أجنبي بلا أثر على بصير؛ توجد نسخة مسبقة وخطة استعادة؛ لا تُنشر أسرار في السجل أو Git.
- **الافتراضات المحافظة:** 15 مستخدمًا متزامنًا كحد تصميم أولي، استخدام ERP يومي مع عمليات تقارير ورواتب دورية، واحتفاظ إنتاجي طويل. لا يوجد اعتماد على القياس الحالي كضمان سعة؛ إعادة تقييم لازمة عند تجاوز هذا الحمل أو نمو التخزين.
- **خريطة ERP:** تظل `account.move` والمدفوعات والمصالحات ومسيرات الرواتب الأصلية داخل Odoo/PostgreSQL مصدر الحقيقة. النشر لا يعدّل عمليات أو قيودًا قائمة؛ الاستعادة تشمل قاعدة البيانات والـfilestore كوحدة واحدة، ولا يُقبل استبدال بيانات حية دون نسخة متسقة وموافقة تشغيلية منفصلة.

## المعمارية والحدود (G2)

```text
Internet (بعد DNS/HTTPS فقط)
  -> nginx المضيف: ملف vhost مستقل لبصير
    -> 127.0.0.1: منفذ Odoo خاص ببصير
      -> baseer-odoo-prod شبكة front
        -> Odoo 19 + addons read-only + filestore volume خاص
        -> baseer-odoo-prod شبكة db (داخلية)
          -> PostgreSQL 16 + volume بيانات خاص
```

- لا تنضم حاويات بصير إلى شبكات `baseer-erp-private-online` أو `arzobs` أو `n8n` أو غيرها.
- لا يستخدم PostgreSQL منفذًا عامًا؛ وصول Odoo إلى قاعدة البيانات عبر شبكة Docker الداخلية فقط.
- nginx هو حد مضيف مشترك وحيد، ويكون ملفه لبصير مستقلًا وقابلًا للإزالة من دون تغيير ملفات المواقع الأخرى؛ لا يُكتب قبل الدومين.
- أسماء المشروع/المجلدات/volumes لا تبدأ أو تتطابق مع مشروع قائم. الاستعادة لا تستعمل إلا backup بصير المعرّف.

## التقنية والمكتبات (G3)

- **المسار المباشر:** إعادة استخدام Compose الحالي وصورة Odoo 19 المثبتة بالبصمة في المشروع وPostgreSQL 16؛ لا Docker Manager ولا مكتبة UI ولا رصة Node جديدة.
- **البدائل المستبعدة:** تثبيت Docker Manager (طبقة إدارة غير لازمة)، مشاركة PostgreSQL أو شبكة مشروع قائم (تخالف العزل)، وفتح Odoo مباشرة على 80/443 (يتعارض مع nginx والمواقع القائمة).
- **أوامر التحقق:** `docker compose config`، فحص أسماء networks/volumes، healthchecks، اتصال داخلي، backup/restore على نسخة معزولة، وفحص HTTP بعد الربط.
