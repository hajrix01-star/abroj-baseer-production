## G2 numeric, security and metric contract — draft for independent review
Base domain is always posted moves AND native user-supplied search domain; native allowed-company record rules remain authoritative. Multiple selected companies may be shown, but company-currency groups must remain separate; never add different currencies. Each currency group has compact customer/supplier rows across five cards. Common foreign invoice row displays its document currency; card totals use native signed company-currency values.

Invoice population: out_invoice/out_refund/out_receipt for customers, in_invoice/in_refund/in_receipt for suppliers. Signed native totals/residuals: multiply supplier values by minus1; refunds subtract. General entries never enter invoice card totals. Labels explicitly say net invoices and settled rather than claiming bank cash. Existing invoice dates/posted dates filters select documents; balances are their current native settlement state, not historical as-of balances.

Five cards per direction: net invoice amount; settled amount (signed total minus signed residual, including credit/write-off settlement); outstanding signed residual; partially paid document count (native payment_state=partial); overdue signed open installment amount (native receivable/payable payment-term lines with date_maturity<today and nonzero residual). Do not use whole invoice residual for an installment amount. Source fields stay native; native payment_state remains unchanged, including not_paid/partial/in_payment/paid/reversed. No recalculation of payment statuses or financial posting.

Server performs exact decimal aggregation over database numeric casts, with currency-rounding/Western formatted strings. Use native account.move._search and account.move.line._search query FROM/WHERE so all model access/company/payroll privacy rules apply; NEVER sudo, bypass_access, broad raw SQL or client-computed money. Return small grouped aggregates and server-owned card domains. A nonstored searchable settled flag may compare native total/residual in a parameterized SQL subquery, while the outer ORM search retains all record rules. Overdue drill-down uses native line-domain semantics matching the aggregate. Fixed public endpoint permission gate requires native invoice/read-only accounting role, excludes cashier via existing denied account.move access. No new ACL/group grants. Core/native source remains unchanged; new addon depends on installed account and baseer_access_roles.

Avoid cross-currency netting and double-counting, preserve date/partner/company filters on card clicks, guard stale asynchronous responses. No sums of generic journal entry turnover mixed with invoice amounts. Ordinary native list export/open respects existing access; no new mass-post/delete/edit operation.

## Independent G0–G3 gate review — icons_release

Decision: APPROVED for implementation of the bounded FL1 read-only feature. This is design approval, not release GO. Reuse accepted AR2 access/privacy architecture; no new financial posting or broad ACL grants are authorized.

The following clarifications are binding parts of the implementation contract:

1. The KPI endpoint explicitly rejects the cashier preset and requires the documented native accounting access. Do not presume cashier has zero account.move read access: native POS grants may legitimately permit session-linked entries. Keep those existing POS rights. Feature navigation/views restrict the register; underlying native model APIs remain governed by their existing permissions.
2. Mobile uses a native kanban alternative alongside list/form, selected for a small screen, with the same posted domain, access rules, record navigation and KPI context. Horizontal scrolling alone is not the promised mobile acceptance.
3. Overdue aggregation intersects the filtered account.move._search query AND the account.move.line._search query, including both models' record rules. Use signed receivable/payable installment residuals and exactly the same maturity/open/account-type predicate for drill-down, without materializing an unbounded document-ID list.
4. A settled contributor is a nonzero signed total-minus-residual difference at the applicable currency rounding, including negative refund contributors. Do not use only a positive difference. Keep customer/supplier directions and each company-currency group separate; do not aggregate journal-entry turnover into invoice cards.
5. All totals describe current native settlement of the filtered posted document population. They are neither cash receipts/disbursements nor historical as-of balances. Empty states contain real zeros, and labels preserve this distinction.

Native ORM-derived SQL sources, parameterized predicates, exact decimal aggregation and bounded grouped payloads are suitable. Existing query/field access restrictions, AR2 payroll/partner privacy and allowed-company checks must hold for rows, cards and drill-down. Existing owner/manual accounting permissions remain unchanged. No arbitrary privileged original-source lookup is permitted; any related-source action checks normal access and uses fixed known links.

G1 capacity values are test assumptions: measure the actual isolated fixture and report its size/latencies honestly. Do not certify the proposed 100000-move/20-reader target without representative evidence. Keep current posting activity separate from read-only KPI calculations and protect against stale UI responses. G4–G8 acceptance must cover the finite financial cases, own/cross-company/privacy boundaries, owned removable filter parity, desktop/480px behavior and exact source release preservation. Implementation may proceed with these constraints; no additional architecture cycle is required for unchanged paths.
