# بصير لنقاط البيع — حزمة واحدة

ثبّت **Baseer POS Suite** مرة واحدة من التطبيقات. تظهر الحزمة كتطبيق واحد في مرشح Apps، وتثبّت داخليًا الطباعة، تصميم الإيصال، والتعديل الموثق. بقاء هذه الاعتماديات في قائمة الموديولات التقنية مقصود؛ لا تلغِ تثبيتها لإخفائها، لأنها تملك البيانات والسجلات.

من **بصير لنقاط البيع ← نقاط البيع والميزات** افتح الكاشير لضبط الميزات. ومن **الطباعة المباشرة** تصل إلى المهام وسجلات المطبخ والتعديل وأجهزة Windows. الاقتران وإدارة الأجهزة لمسؤول النظام فقط، والتقارير لمدير نقاط البيع، مع صلاحيات الشركات الأصلية.

## التركيب والترقية

1. خذ نسخة قاعدة البيانات وملفات المرفقات، وحدد إصدار المصدر السابق للاسترجاع.
2. ضع المجلدات الأربعة `baseer_pos_suite`, `baseer_pos_print_bridge`, `baseer_pos_receipt_layout`, `baseer_pos_product_substitution` في مسار إضافات واحد. تأكد أنه لا توجد نسخة أقدم تسبقه في addons_path.
3. على Odoo 19، حدّث قائمة التطبيقات ثم ثبّت الحزمة. عند ترقية تركيب موجود، حدّث **الموديولات الأربعة** في دورة صيانة واحدة؛ تحديث الحزمة وحدها لا يضمن تحديث مخطط/أصول الاعتماديات المعدلة. لا تعدّل نواة أودو.
4. راجع الشركات والطابعات ونقاط البيع. استخدم معالج إعداد الطباعة الموجود للاقتران؛ ملفات الحزمة لا تحتوي مفاتيح أو صلاحيات أجهزة جاهزة.
5. اختر شكل الإيصال الأصلي أو بصير80mm لكل كاشير. إعداد الشركة الافتراضي يطبّق على الكاشيرات الجديدة فقط؛ لا يغيّر الموجودة تلقائيًا.
6. اختبر فتح الطلب، التعديل/الإلغاء، الدفع، إعادة الفتح، الطباعة الفعلية، رقم الضريبة وQR، وإغلاق الجلسة في نسخة مطابقة للحي أولًا.

تعطيل الحزمة/إزالتها ليس زر تعطيل جميع الوظائف: إزالة الحزمة تعيد قوائم الطباعة لموضعها الأصلي وتترك الاعتماديات والبيانات. التحكم بالميزات من الإعدادات؛ لا تحذف موديولًا يملك سجلًا تاريخيًا.

## ما لا ينتقل بملفات الإضافات

- Windows Print Agent برنامج مستقل. مصدر الحزمة يطابق الإصدار1.5.11 المعتمد في QA2؛ لا يعني ذلك أن كل جهاز يعمل بهذا الإصدار. افحص الإصدار الفعلي وأعد الاقتران حسب الشركة والجهاز. لا تتضمن هذه الحزمة مثبتًا تلقائيًا أو خدمة تحديث تلقائي.
- يلزم HTTPS صالح وإعداد reverse proxy مع `/websocket` إلى منفذ Odoo8072 عند استخدام workers، وباقي الطلبات إلى8069. حافظ على رؤوس البروكسي من مصدر موثوق؛ قالب QA ليس إعداد نشر حي جاهزًا.
- الضرائب والحسابات والمنتجات والشركات إعدادات قاعدة بيانات. صيغة رسوم التبغ المستخدمة في QA تحتاج الإضافتين الأصليتين `account_tax_python` و`pos_account_tax_python` وترتيب الضرائب الصحيح. لا تُنشأ رسوم أو حسابات أو منتجات QA تلقائيًا؛ راجعها للشركة المستهدفة.
- إضافة الرقم الضريبي وظهور QR ليسا شهادة امتثال أو ربط بمنصة فاتورة؛ الربط النظامي منفصل.

## حدود الاعتماد

فحص QA2 بتاريخ2026-09-23 لم يجد تعديلًا في ملفات كود Odoo المثبتة بالصورة الرسمية. إصلاحات السلوك داخل إضافات بصير، وإصلاح WebSocket في إعداد البروكسي. نجاح QA لا يضمن كل سيناريو أو جاهزية Live قبل فحص بيئته. هذه الحزمة مصدر مرشح QA وليست نشرًا حيًا.
