# PAU1 — التحديث التلقائي لوكيل الطباعة

## عقد البناء — G0 (مسودة)

**الهدف.** تجعل نسخة Windows المثبّتة من `Baseer Print Agent` تتحقق دورياً من
إصدار منشور ومعتمد، ثم تثبّت نسخة أحدث تلقائياً وبصورة قابلة للاسترجاع، من دون
أن يضطر مسؤول المطعم إلى تنزيل ملف جديد يدوياً في كل إصدار.

**المستخدمون.** مسؤول أودو الذي ينشر الإصدار، وموظف المطعم الذي يستعمل الطباعة؛
لا يُطلب من موظف الكاشير أي إجراء أثناء التحديث.

**النطاق.** وكيل Windows، مركز الوكيل في Odoo، وإصدار GitHub العام. لا يغير
الطباعة أو الطوابير أو إعدادات الطابعة أو الطلبات أو بيانات المبيعات.

**الرحلة الحرجة.** ينشر المسؤول إصداراً محدداً مع رابط GitHub وSHA-256؛ يقرأ
الوكيل البيان المعتمد عبر Odoo، يقارن النسخة، ينزّل الملف إلى مسار مؤقت، يتحقق
من SHA-256، ينتظر إكمال مهمة الطباعة الحالية، يستبدل النسخة ويشغّل النسخة الجديدة.
أي فشل يبقي النسخة العاملة ويُسجَّل كحالة قابلة للتشخيص.

**معايير القبول.**

1. لا يقبل الوكيل رابطاً أو تجزئة غير معتمدين من Odoo.
2. لا يجري تحديثاً مساوياً أو أقدم من النسخة المثبّتة، ولا يعمل أكثر من مُحدِّث
   واحد في الوقت نفسه.
3. تحقق SHA-256 إلزامي قبل الاستبدال؛ لا يُشغّل ملف غير متحقق منه.
4. لا تُفقد أو تتكرر مهمة طباعة جارية؛ يؤجل التحديث حتى لا توجد مهمة نشطة.
5. عند فشل التنزيل أو التحقق أو التشغيل، تبقى النسخة السابقة قابلة للتشغيل مع
   سجل تشخيصي، ولا تُعرض أسرار أو بيانات مبيعات.
6. يعرض مركز الوكيل النسخة والرابط والحالة بالعربية والإنجليزية؛ رابط GitHub
   العام لا يحل محل ربط جهاز جديد الآمن.

**خارج النطاق.** تحديث Odoo نفسه، تحديثات غير Windows، تثبيت تلقائي أولي على
كمبيوتر جديد، وتغيير إعدادات أو تعريفات الطابعات.

**افتراضات.** GitHub Releases هو مصدر الملفات العام؛ Odoo هو مصدر قرار الإصدار
المعتمد. إصدار أولي يحتاج صلاحية Windows القائمة؛ التحديثات اللاحقة تعمل ضمن
مسار الوكيل المثبّت. التوقيع الرقمي للملف سيُفحص في G2 قبل تقرير ما إذا كان
SHA-256 المعتمد وحده كافياً أو يلزم Authenticode.

## ملف السعة والاستمرارية — G1 (مسودة)

| بند | تقدير محافظ قابل للقياس |
|---|---|
| المستخدمون/الأجهزة | حتى 100 جهاز وكيل نشط؛ ذروة تحقق متزامن بعد النشر 100 جهاز |
| العمليات | طلب بيان تحديث كل 6 ساعات مع تأخير عشوائي؛ تنزيل فقط عند وجود إصدار أحدث |
| البيانات | سجل إصدار صغير لكل نسخة؛ الملف يبقى في GitHub ولا يُخزّن كـ attachment في Odoo |
| الأداء | لا يؤثر فحص التحديث في دورة استلام مهمة الطباعة؛ مهلة الشبكة محددة وإعادة محاولة لاحقة |
| التزامن | قفل عملية محلي لكل وكيل؛ لا تحديث أثناء مهمة طباعة أو مع نسخة وسيطة |
| الاستمرارية | حفظ النسخة القديمة مؤقتاً حتى نجاح تشغيل البديلة؛ سجل محلي للحالة والخطأ؛ إصدار سابق معتمد متاح للتراجع |

## القرار الأولي — سؤال المسار المباشر

المسار المباشر هو **بيان إصدار معتمد من Odoo + ملف GitHub Release ثابت + تحقق
تجزئة داخل الوكيل**. لا نضيف خدمة تحديث مستقلة ولا مكتبة تحديث خارجية. إبقاء Odoo
صاحب قرار الاعتماد يمنع تنزيل أي GitHub release عشوائي، وإبقاء GitHub صاحب الملف
يلغي تكرار ملف كبير داخل قاعدة بيانات Odoo.
