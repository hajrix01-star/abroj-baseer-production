## الخريطة وحدود السلطة

أعيد استخدام سجل المعمارية `docs/architecture/registry/INDEX.md` وعقد `docs/build-governance/PARTNER-PRIORITY.md`؛ الدلتا المثبتة بالكود:

`native partner selectors → native web_name_search / web_search_read → current-company partner domain → company-dependent favorite + rule-filtered account.move aggregate → native pagination → native autocomplete/star`

`native boolean_favorite → native partner write ACL/rules + company guard → company-dependent JSONB`

الفواتير الأصلية هي المصدر الوحيد لعدد الاستخدام. الحساب في SQL قبل ترقيم الصفحات، دون sudo أو قائمة موردين كاملة في الذاكرة أو عداد محفوظ أو خدمة إضافية. لا تغيير للأسماء أو القيود أو مبالغ الفواتير أو دورة اعتمادها. ترتيب المبيعات يستخدم نفس تفضيل الموردين وعدد فواتير المشتريات وفق العقد؛ لا يخترع عداد مبيعات آخر.

## التغطية والدليل

مراجعة مركزة للملفات التسعة، وبعمق أكبر لعزل الشركات وقواعد القراءة والكتابة. جُمعت أدوار المعمارية والأمان وERP وبساطة التنفيذ والتبعيات وحراسة المرشح لدى المراجع المستقل لتجنب تكرار العمل؛ لم تنشأ مهارات أو تبعيات أو وكلاء إضافيون. الواجهة والتحقق التشغيلي أعدهما قائد التنفيذ وتراجع أدلتهما هنا.

- راجعت `checks.py` ونتيجته `checks.json`: 28 حالة ناجحة، تشمل ثلاث شركات، إزالة التفضيل، تاريخ اليوم واليوم 89 واستبعاد 90 والمستقبل والمسودات والملغاة والمرتجعات، البحث المطابق، LIMIT/OFFSET وSearch More، مجال المبيعات والدفعات، عدم تعديل الأسماء، انعدام صلاحية قراءة الفواتير، قواعد الفواتير، ورفض سياق الشركة المزور. هذه أدلة قائد التنفيذ ولم أعد تشغيلها.
- شغلت مستقلًا `independent_checks.py` بواسطة Odoo shell في QA الخاصة: 6 حالات ناجحة موثقة في `independent-checks.json` و`independent-checks-output.txt`. تغطي رفض إنشاء مفضّل خاص بشركة أخرى صراحة وعبر default السياق، إخفاء جهة شركة أخرى في Search More مع السماح بالشركتين، احترام قاعدة منع كتابة جهة الاتصال وبقاء القيمة بعد الرفض، وإرجاع نجمة الاختيار لمستخدم بلا قراءة فواتير. أعيدت جميع بيانات الاختبار بـrollback.
- راجعت `preservation.py` و`preservation.json`: تطابق الصفوف والأعمدة الأصلية في 277 جدول أعمال، بما فيها جهات الاتصال والشركات. استُبعدت فقط معرفات صفوف الاختبار الإضافية في QA؛ العمود الجديد ليس جزءًا من الأعمدة القديمة. لا يدل ذلك على فحص جميع جداول النظام أو نشر إلى MAIN.
- راجعت `capacity.py` و`capacity.json`: 10,000 جهة و100,000 فاتورة اصطناعية، LIMIT 8 ونتيجة التفضيل قبل الحد. وسيط القراءات الدافئة 42.51ms بعد ANALYZE، قارئ واحد. لا شهادة 20 مستخدمًا متزامنًا ولا قياس قدرة اعتماد فواتير. صلاحية النتيجة تعتمد على إحصاءات PostgreSQL المحدثة؛ التجربة الأولى دون تحديثها تجاوزت الهدف، وسجلت في العقد.
- لا حزمة خارجية، ولا أصل vendor/core معدل، ولا صلاحيات جديدة. إعادة استخدام BooleanFavoriteField وMany2XAutocomplete والترجمة الأصلية، مع أيقونة منفصلة لا تلوث الاسم.
