# ABROJ-WEB-1 — موقع أبرج وبوابة دخول بصير

## عقد البناء (G0 — قيد المراجعة)

**الهدف.** إطلاق واجهة مؤسسية ثنائية اللغة لشركة **أبرج للمشاريع المتكاملة** في الخبر (إنشاءات، مبانٍ، أسفلت وطرق، وتكييف)، مع شاشة دخول بصير احترافية وبسيطة تستعمل مصادقة Odoo الأصلية.

**المستخدمون والرحلات الحرجة.**

1. زائر عربي أو إنجليزي يصل إلى `abroj.sa`، يقرأ نبذة موجزة عن أبرج وخدماتها، وينتقل بين أقسام رأس الصفحة أو يتواصل مع الشركة.
2. موظف يصل إلى `baseer.abroj.sa`، يختار لغته، يدخل ببياناته المعتمدة في Odoo ثم ينتقل إلى `/web` من دون مسار مصادقة موازٍ.
3. لاحقاً فقط: جهاز حضور على `kiosk.abroj.sa` يستعمل كشك الحضور الأصلي في Odoo؛ لا يدخل ضمن هذه الشريحة.

**النطاق.** موقع صفحة واحدة مختصر ذو تنقل رأسي من الرأس (الرئيسية، من نحن، خدماتنا، القطاعات، تواصل)، ومحتوى عربي/إنجليزي أصلي، وصور إنشاءات حقيقية مرخّصة أو يملكها العميل. موديولان خفيفان: موقع Odoo Website لأبرج، وتخصيص بصري لقالب `web.login` لبصير فقط.

**خارج النطاق.** لا نظام دخول جديد، ولا Controller مصادقة مخصص، ولا SSO، ولا جمع بيانات تشغيلية أو مالية، ولا تعديل قيود/رواتب/حضور، ولا نشر أو تغيير DNS أو تثبيت في MAIN.

**معايير القبول.**

- الهوية تستعمل الاسم «أبرج» حصراً، واللغتين العربية/الإنجليزية وRTL/LTR من المصدر.
- الموقع لا يشبه قالباً جاهزاً أو مخرجاً آلياً: شبكة تحريرية هادئة، صور حقيقية، وكتابة مهنية محددة.
- شاشة بصير تحتفظ بـ Odoo القياسي كسلطة وحيدة للجلسة وكلمة المرور وإعادة التعيين والصلاحيات وCSRF والتحويل بعد الدخول.
- سطح المكتب والجوال (من 360px)، لوحة المفاتيح، التباين، وحالة التركيز قابلة للاستخدام.
- لا تعرض الصفحة أرقاماً تجارية أو مالية؛ كل أرقام الواجهة — إن وجدت — غربية `0-9`.

**الافتراضات المعلنة.** الاسم التجاري المعروض هو أبرج للمشاريع المتكاملة، والمقر الخبر، وسنة التأسيس 2018، والخدمات المعتمدة هي الإنشاءات والمباني والأسفلت والطرق والتكييف. لا نختلق مشاريع أو شهادات أو أرقام اتصال أو عملاء. ستستخدم الصور المرخّصة الحقيقية مؤقتاً إلى أن يزود العميل بصور أبرج.

**دورة ERP والرقابة.** لا توجد عملية مالية أو ترحيل أو راتب أو أثر محاسبي في هذه الشريحة. Odoo لا يزال مصدر الحقيقة للهوية والصلاحيات فقط؛ كشك الحضور مؤجل ويتبع تطبيق Attendances الأصلي.

## ملف الإطلاق والنمو (G1 — مسودة)

- افتراض إطلاق محافظ: حتى 100 زائر متزامن للموقع و30 محاولة دخول متزامنة في الذروة، مع نمو محتوى محدود وصور مضبوطة الحجم.
- الرحلات الحساسة: عرض الصفحة العامة، تحميل `/web/login`، وتقديم نموذج Odoo القياسي. هدف الصفحة العامة وواجهة الدخول هو عرض أولي سريع على شبكة جوال؛ لا يوجد وعد سعة قبل قياس QA.
- لا تخزين جديد ولا schema أو استعلامات أو طوابير. ملفات الصور لا تسجل بيانات زائر. يسجل Odoo محاولات الدخول طبقاً لسلوكه القائم.
- الاستمرارية: HTTPS وreverse proxy و`proxy_mode` و`dbfilter` و`--no-database-list` إلزامية عند النشر؛ لا تعرض منافذ Odoo مباشرة. النسخ والاستعادة تبقى مسؤولية تشغيل Odoo القائمة.

## المعمارية والعقود (G2 — مسودة)

```mermaid
flowchart LR
  V[زائر] --> W[abroj.sa: Odoo Website]
  E[موظف] --> L[baseer.abroj.sa: web.login ذو هوية بصير]
  L --> A[مصادقة Odoo القياسية]
  A --> B[/web والصلاحيات القائمة]
  K[كشك لاحقاً] --> H[Odoo Attendances Kiosk الأصلي]
```

- `baseer_abroj_login` يرث QWeb والأصول فقط؛ لا يعرّف route أو controller أو منطق جلسة.
- `abroj_website` يملك القالب والمحتوى والثيم المحدود لموقع أبرج، ويعتمد على `website` فقط.
- المحتوى العام ثابت ومتعدد اللغات في XML/ترجمات الموديول. لا يقرأ الموظفين أو الحضور أو الرواتب.
- النطاقات النهائية يضبطها reverse proxy خارجي بعد قبول مرشح QA؛ لا تغيير DNS أو شهادة ضمن هذا العقد.

## التقنية والمكتبات (G3 — مسودة)

- المسار المباشر: QWeb وSCSS وأصول Odoo الموجودة، ولا مكتبات JavaScript أو قوالب طرف ثالث أو تعديل Odoo core.
- الخطوط: خط ويب احترافي مرخّص/مفتوح يدعم العربية واللاتينية (يُتحقق من الترخيص قبل تضمينه)، مع بديل نظامي مناسب. لا تنزيل اعتماد جديد قبل توثيق مصدره وترخيصه.
- صور الواجهة: صور فوتوغرافية حقيقية مرخّصة فقط، مع نص بديل عربي/إنجليزي، أبعاد ثابتة وتحميل مناسب للجوال.

## نظام التجربة والواجهة (G4 — مسودة)

- التوكنات المركزية: كحلي أبرج `#063761`، أزرق فاتح مساعد، أبيض/رمادي حجري هادئ، وتركيز واضح؛ ألوان الحالة تبقى ملك Odoo.
- الخطوط: Sans عربي/لاتيني احترافي واحد متناسق أو ازدواج متوافق؛ لا خطوط عرض زخرفية أو تدرجات أو زجاجيات أو بطاقات تسويقية متكررة.
- مكونات الموقع: `AbrojHeader` و`Section` و`ServiceList` و`ContactPanel` و`Footer` ضمن موديول الموقع؛ `BaseerLoginShell` ضمن موديول الدخول. لا ترقية عنصر خاص قبل تكراره.
- الحركة هادفة فقط: انتقال لون/شفافية قصير وزر ضغط؛ لا حركة عند التنقل المتكرر ولا حركة لمن يفضّل خفض الحركة.

## ملحق الإقفال قبل البناء (AW-003)

**سطح Website وتشغيله.** التسجيل العام يبقى معطلاً؛ الاستعادة القياسية لكلمة المرور تتبع إعداد Odoo المعتمد فقط. `abroj_website` يعتمد على `website`، وWebsite يعتمد انتقالياً على `digest`, `web`, `html_editor`, `http_routing`, `portal`, `social_media`, `auth_signup`, `mail`, `google_recaptcha`, `utm`, `html_builder` و`geoip2`. لا يفترض وجودها في MAIN: يثبت/يرقى Website في QA مطابق أولاً، مع نسخة قابلة للاستعادة، ثم تختبر أصول `web.assets_frontend` دون أثر على الموديولات القائمة. Website قد ينشئ بيانات زائر/كوكيز وفق سلوكه القياسي؛ أبرج هي مالكة قرار سياسة الخصوصية والموافقة قبل النشر، ولا نضيف تحليلاً خارجياً.

**المضيفون.** سجل Website المقصود هو `https://abroj.sa` فقط، وسيحوّل `www.abroj.sa` دائماً إلى النطاق المجرد عند النشر. لا يترك اختيار Website إلى fallback. يحوّل reverse proxy صراحة `baseer.abroj.sa/` إلى `/web/login` في قاعدة Odoo المقيدة؛ لا ينشأ له سجل Website ولا يهبط على موقع أبرج. لا تتغير DNS أو الشهادات هنا. قبل أي وصول عام: HTTPS، reverse proxy موثوق، `proxy_mode=True`، `dbfilter` لقاعدة واحدة، `list_db=False`/`--no-database-list`، ومنع وصول الإنترنت المباشر إلى منفذ Odoo. الإعداد المحلي الحالي ليس إعداد نشر.

**السعة والأصول.** الحد الأقصى ثلاث صور فوتوغرافية رئيسية بصيغة WebP/AVIF حيث تسمح الأداة وبعرض مناسب وشبكة تسليم مخبأة عند النشر. لا تعتمد الرحلة العامة على CDN صور أو خط طرف ثالث بلا موافقة. في QA يجب أن تعرض الصفحة العامة و`/web/login` بلا خطأ HTTP أو مورد محظور، وعلى جوال 360px وسطح المكتب؛ لا وعد بأرقام زمن أو سعة إنتاج قبل قياس معزول.

**الخطوط والصور.** تستخدم `Noto Sans Arabic` للعربية و`Noto Sans` للإنجليزية بالأوزان 400 و500 و700، تحت SIL Open Font License 1.1، بالاستفادة من أصول Noto الداعمة لـUnicode التي يوفرها Odoo ومن دون تنزيل طرف ثالث؛ fallback هو `system-ui, Arial, sans-serif`. المواضع التصورية الحالية متسقة بأسلوب «رسم هندسي → تنفيذ ملوّن»: مبنى، شبكة HVAC، وطريق/رصف، وتعرض بصفتها تصورات توضيحية لا مشاريع أبرج المنفذة. أي صورة فعلية تدخل لاحقاً بمصدر/ترخيص مسجل وتحل محلها بعد اعتماد الشركة.

**خريطة التجربة.** الرأس الثابت القصير يحمل شعار أبرج و`الرئيسية/Home` و`من نحن/About` و`الخدمات/Services` و`القطاعات/Sectors` و`تواصل/Contact`، وزر الإجراء الوحيد `تحدث معنا / Talk to us`. الأقسام: افتتاحية هادئة، تعريف موجز منذ 2018، قائمة خدمات عملية، قطاعات التنفيذ، ولوحة تواصل؛ لا أرقام أو شهادات أو عملاء غير موثقة. يضبط العربي `lang="ar" dir="rtl"` والإنجليزي `lang="en" dir="ltr"`؛ الشعار والقائمة والأيقونات تتبع الاتجاه، وزر اللغة يعيد إلى القسم نفسه. نموذج بصير يرث اتجاه لغة Odoo، وتبقى قيم البريد وكلمة المرور LTR. نقاط التوقف: 360–767px رأس قابل للفتح بلوحة المفاتيح وعمود واحد، 768–1023px لوحي، و1024px فأعلى سطح مكتب.

**نظام التصميم والتحقق.** التوكنات: كحلي أبرج `#063761`، أزرق مساعد `#1678A2`، سطح `#F5F7F8`، حبر `#102A3A`، نص ثانوي `#52616B`، حدود `#D5DEE3` وتركيز `#1678A2` بعرض `3px`. لا تدرجات أو زجاجيات أو بطاقات تسويقية متكررة. الحركة تقتصر على لون/شفافية `160ms` وضغط `scale(.98)`، وتحترم `prefers-reduced-motion`. تحقق G5 يغطي العربية والإنجليزية، RTL/LTR، 360px، لوحة المفاتيح وحلقة التركيز، والحالات العادية والخطأ واستعادة كلمة المرور في بصير.
