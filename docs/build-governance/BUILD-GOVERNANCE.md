# حوكمة بناء ونشر بصير أودو

## الحالة السارية — 2026-09-16

هذا المستند هو المرجع التشغيلي الوحيد للنشر والاسترجاع. أزيلت منه العقود
التجريبية السابقة، وسياسات SHA الأحادية، ومسارات الأرشيف أو الطرفية اليدوية.
تاريخها محفوظ في Git ولا يصلح لتشغيل الإنتاج.

| المجال | الوضع الساري |
| --- | --- |
| مصدر الكود | `main` في `hajrix01-star/abroj-baseer-production` |
| مسار النشر التشغيلي | يدوي من GitHub Actions؛ غلاف النشر لا يقبل إلا سياسة محفوظة مسبقًا |
| مدخل Action | `release_id` مسمى + كلمة تأكيد ثابتة فقط |
| قرار المكونات وcommit | سياسة إصدار محفوظة على الخادم بصلاحية `root:root,0600` |
| حساب النشر | `baseer_deploy` محدود بغلافي اعتماد/نشر ثابتين؛ لا root ولا Docker عام |
| مصدر الخادم | مفتاح GitHub للقراءة فقط محفوظ `root-only` |
| التزامن | قفل خادم مشترك بين الاعتماد والنشر |
| التراجع | الإصدار السابق + زوج PostgreSQL وfilestore متسق |

## العقد

```text
GitHub: اعتماد release_id
  -> الخادم يثبت سياسة الإصدار: commit كامل + موديولات مسموحة
GitHub: نشر release_id نفسه
  -> الخادم يتحقق من السياسة ويجلب المصدر بنفسه
  -> backup متسق -> ترقية محددة -> health أو rollback كامل
```

لا تعرض الـActions للمستخدم SHA أو قائمة موديولات أو مسار أرشيف؛ الإدخالان
الوحيدان هما `release_id` وكلمة التأكيد الثابتة. يمرر Workflow الاعتماد
`GITHUB_SHA` تلقائيًا كمرجع للسياسة، ثم يتحقق الخادم من السياسة والـcommit
والموديولات بنفسه. أي سياسة غير محمية، أو commit غير موجود على `main`، أو موديول
غير موجود في ذلك commit، أو نقص في السعة، يوقف العملية قبل توقف أودو.

## حدود حماية GitHub

بيئة GitHub المسماة `production` مستخدمة في الـActions، لكن لا توجد قاعدة
مراجعين إلزاميين أو تقييد فروع ظاهر في إعداد البيئة الحالي. الحماية المثبتة
حاليًا هي التشغيل اليدوي من `main`، كلمات التأكيد، مدخلات محدودة، حساب SSH
مقيد بأغلفة `sudo` ثابتة مع تعطيل TTY والتحويلات، وسياسة خادمية `root-only`.
إضافة مراجعين إلزاميين أو حماية فروع قرار حوكمة لاحق وليست حماية ندّعي وجودها
الآن.

## PRC-3 — إنشاء Petty Cash للمحاسب وحصر تعديلها بالمالك (2026-09-17)

- **الهدف:** المحاسب ينشئ صندوق Petty Cash، بينما يظل التعديل والحذف والإقفال
  للمالك فقط. الاسم الإنجليزي الظاهر يصبح `Petty Cash` مع بقاء المعرفات
  التقنية وسجل الحركات كما هما.
- **المسار المباشر:** ACL منفصل للمالك بصلاحيات كاملة، وإنشاء فقط للمحاسب
  ومدير المشتريات؛ لا نعتمد إخفاء زر الواجهة كحماية. لا نغيّر أي قيد أو حركة
  أو اسم تقني أو تسلسل موجود.
- **التحقق المطلوب:** إنشاء المحاسب مسموح، و`write`/`unlink`/الإقفال مرفوضة
  له؛ المالك يملك العمليات الأربع والإقفال. تُراجع الترجمة العربية بعد تحديث
  الموديول.
- **تحقق معزول:** تحميل الموديولات والترجمة نجح، واختبار الصلاحيات الفعلي
  (`CashierProcurementRoleCase.test_cpr_t00b...`) نجح: المحاسب أنشأ الصندوق
  لكنه مُنع من التعديل والحذف والإقفال؛ المالك اجتاز فحص الإنشاء والتعديل
  والحذف ثم الإقفال.
- **دليل الحي:** نجحت موافقة الإصدار
  [`35152744507`](https://github.com/hajrix01-star/abroj-baseer-production/actions/runs/35152744507)

  `Petty Cash` في شاشة الإقفالات بعد تحديث الموديولات، مع بقاء العرض العربي

## PRC-4 — فتح نموذج Petty Cash الجديد (2026-09-17)

- **السبب:** احتساب الأرصدة في نموذج جديد لم يكن له سجل محفوظ كان يرسل
  استعلام PostgreSQL بصيغة `IN ()`، فيفشل فتح شاشة الإضافة فقط.
- **المعالجة:** تعيين الأرصدة إلى صفر قبل الحفظ بدل تنفيذ الاستعلام؛ لا تغيير
  في السجلات أو القيود أو الحسابات القائمة.
- **التحقق:** اختبار نموذج جديد نجح دون خطأ وبأرصدة صفرية. نجحت موافقة

## PRC-5 — وضوح نموذج Petty Cash قبل الحفظ (2026-09-17)

- **السبب:** لوحة الأنشطة العريضة كانت تخفي أدوات أودو القياسية للحفظ أو
  الإهمال عمليًا، كما أن الحركات والإقفال ظهرت قبل إنشاء الصندوق.
- **المعالجة:** تُحدَّد لوحة الأنشطة بعرض مناسب على الشاشات الواسعة، وتصبح
  العناوين مختصرة. قبل أول حفظ لا تظهر الحركات أو الإقفال؛ تظهر رسالة موجزة
  ثم يظل للمستخدم الحفظ أو الإهمال دون إنشاء أي سجل.
- **التحقق:** تحميل الموديول واختبار Petty Cash القائم نجحا محليًا. نجحت
  الموافقة [`35154010627`](https://github.com/hajrix01-star/abroj-baseer-production/actions/runs/35154010627)
  ثم النشر [`35154041150`](https://github.com/hajrix01-star/abroj-baseer-production/actions/runs/35154041150).
  تحققنا حيًا بحساب ARZ: ظهرت أزرار الحفظ والإهمال، ولم تظهر الحركات أو
  الإقفال، ثم نجح الإهمال وعاد للقائمة دون إنشاء عهدة.

## PRC-6 — حفظ عهدة المحاسب مباشرة (2026-09-17)

- **السبب:** صلاحية الإنشاء بلا `write` منعت واجهة أودو من إظهار زري الحفظ
  والإهمال للمحاسب، رغم أن سياسة العمل تسمح له بإنشاء العهدة.
- **المعالجة:** يُمنح المحاسب `write` اللازم للواجهة الجديدة فقط؛ طبقة النموذج
  تمنع أي كتابة أو حذف لسجل محفوظ لغير المالك. إنشاء العهدة يحفظها مباشرة
  بحالة «مفتوح» بلا موافقة أو خطوة اعتماد لاحقة. حقول تعريف العهدة المحفوظة
  تظهر للقراءة فقط للمحاسب حتى لا تعرض واجهة قابلة للتعديل ستُرفض عند الحفظ.
- **التحقق:** نجح اختبار الصلاحيات المحلي للحالة الجديدة. وعلى اللايف بحساب
  المحاسب ظهرت العهدة المحفوظة بحالة «مفتوح» وحقول تعريفها للقراءة فقط، بلا زر
  إقفال؛ ولم تُنشأ أي حركة مالية أثناء الفحص. نُشر الإصدار المعتمد عبر
  [اعتماد الإصدار](https://github.com/hajrix01-star/abroj-baseer-production/actions/runs/35155215602)
  ثم [النشر](https://github.com/hajrix01-star/abroj-baseer-production/actions/runs/35155255635).
