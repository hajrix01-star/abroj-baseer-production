# NX-ODOO-ONLY — المبيعات المنقولة إلى أودو

## العقد والبوابات G0–G3 (قيد المراجعة)

توجيه المالك: نوركس سيُترك؛ المطلوب ظهور المبيعات المرحلة الموجودة بأودو دون ربط خارجي أو استيراد بيانات إضافية. التطبيق Odoo19، baseline f5e90c305؛ دلتا ARCHITECTURAL محدودة بقارئ تقرير المبيعات المشترك والتقويم. المصدر التنفيذي المرجعي NSI وسجل registry الحالي، لا إعادة استكشاف للنظام.

- G0: رحلة المالك: تفعيل الخيار الموجود ثم رؤية مبالغ المبيعات المنقولة وتفاصيل قيودها. لا كتابة حسابات أو مصدر أو evidence، لا اتصال نوركس أو ترحيل. تبقى الأعداد غير المحفوظة مجهولة. خريطة الدورة: قيد مرحل أصلي → قراءة دخل/ضريبة/تمويل من أسطره → تقرير؛ العكس الأصلي بتاريخه وبإشارة مقابلة. لا تغيير ترحيل أو إقفال أو EDI.
- G1: استخدام مالك واحد وتقاريره الحالية؛ المثبت55قيدًا للشركة2 في نطاق التاريخ والمقارنة،5في نوفمبر؛ افتراض محافظ5قراء متزامنين. إعادة استخدام سقف100000صف وميزانية أسطر/عكس ومهلة التقرير الحالية؛ لا وعد سعة جديدة ولا بيئة حمل. لا داعي لإعادة فحص حمل لأننا نضيف مسار قراءة محدود للقيود الموجودة، وتغطيه اختبارات الحدود القائمة وحالات القارئ الجديدة.
- G2: لا schema؛ القيود المرحلة داخل الشركة الحالية هي سلطة المال؛ Decimal بمنزلتين. المرجع الصريح NOORIX-SALES يحدد الشركة المصدرية وتاريخ العمل ومعرّف المصدر. نقرأ الجذور غير المرتبطة بـevidence مع بقاء الموثق أولى وعدم احتساب move مرتين؛ عدد العملاءNone عند غيابه. نفصل تحقق أسطر القيد عن تحقق snapshot لإعادة استخدامه. نحافظ على ACL دونsudo، ورفض تداخل أصلين/مصادر أخرى، وأصل/عكس متسلسل كامل ورفض إخفاء العكس. التاريخ لا يُستنتج من مصدر خارجي.
- G3: Python/ORM/Owl الموجودة، لا مكتبات أو اعتماديات أو خدمة جديدة. تعديلات العرض ضمن المكونات والترجمات القائمة؛ أرقام0–9؛ لا تنسيق أو حركة جديدة.

المسار المباشر: إعادة استخدام القارئ المحاسبي الحالي مع evidence اختياري؛ لا نستورد metadata وهمية ولا نعيد إنشاء المبيعات. القبول: المبلغ من القيد دون عميل مصطنع، نفس المبلغ في التقويم والملخص، عدم التكرار، العكس بتاريخه، عزل الشركات، منع الكتابة/الاتصال، بقاء سلوكOFF.

## السجل الحي

- NX001: قراءة المتطلبات والمراجع والاختبارات وG0–G3. SELECT READ ONLY يثبت مراجع خمسة قيود نوفمبر بتاريخ ومعرّف مصدر صريح؛ لا تغيير بيانات. Docker المحلي غير مشغل؛ التحقق التالي يختار بيئة اختبار معزولة قائمة بعد فحص إعدادها. حارس مستقل يراجع البوابات قبل كود التطبيق.

## التحقق والتسليم

- NX002: حارس البوابات المستقل scoped_delivery اعتمدG0–G3 للتنفيذ المحدود؛ الحالات المعتمدة: عدم تخفيف فحصevidence، عقدevent.customer_count مستقل يقبلNone، هوية(company/source_company/source_id) مشتركة ومنع تكرارmove، وضبطcurrency/date/ACL/budget/reversals. نطاق التنفيذ القارئ والvalidator واختبارات ORM والمستهلك heat فقط؛ لا بيانات ولا نشر. هذه البوابات مقفلة للتصميم المذكور.
- NX003: أعيدتG2 لملاحظة وجودnativeمستقل بنفس يوم القيد المنقول. اعتمد الحارس المستقل أن اليوم ليس هوية قيد؛ ledger-onlyيجمع كل قيد مرحل مستقل مرة بمعرّفmoveوsource، ويرفض روابط أو معرّفاتnativeالمكررة للأصل والعكس؛ تحفظ أحداثEvidence عقدها القديم. العكس يرثledger_onlyصراحة. لا حذف/تجاهل لفاتورة صغيرة ولا تخمين تكرار بمبلغ/يوم. فحصوجودEvidenceمحجوب يقبلSELECT1ثابتًا بمعاملات علىrootالمقروء فقط؛ يرجعوجودًا دون بياناتمحجوبة.

يضاف اختبار ORM يثبت العرض بلاmetadata، حماية الحساب/الصلاحيات والعكس؛ اختبارات Node الحالية15/15 قابلة لإعادة الاستخدام ما لم تتغير الواجهة. لا نشر للايف دون مسارPR/CI والإصدار المحمي. التراجع كودي فقط؛ لا بيانات جديدة تحتاج معالجة.
