# HR1 — ترحيل ملفات الموظفين والرواتب

الحالة: مكتمل في الأصلية للأسماء فقط مع المطابقة. السابقون مؤرشفون والزوجان المكرران مدمجان. الرواتب والبدلات والعقود وجداول الدوام مؤجلة باختيار المالك.

التفويض: طلب المالك استيراد أسماء موظفي بصير القديم إلى الشركات المكافئة في النسخة الأصلية، مع الرواتب والبدلات.

الهدف: `baseer_dev`، المنفذ 18069، المصدر البرمجي الحالي WS3 commit `40dee029c01cf51fa01d233185b3b63805754ce3`.

## العقد والحدود

- البيانات الحالية للموظف وإعداد راتبه فقط؛ لا إنشاء مسيرات أو مدفوعات أو قيود أو أرصدة سلف أو مستندات نهاية خدمة.
- إثبات مصدر البيانات والشركة والحالة وتاريخ سريان الراتب قبل الكتابة؛ لا افتراض أن اسم قاعدة يتضمن test يجعل كل بياناتها تجريبية أو فعلية.
- مطابقة ARZ → 1، المعلم الشامي → 2، دوحة المستهلك → 3 بعد إثبات أسماء المصدر. لا إنشاء شركات غير مقابلة.
- حقل أودو إجمالي الراتب يشمل البدلات؛ مجموع البدلات يدخل مرة واحدة. لا تخمين أساسي/إضافي أو تواريخ عقود ناقصة.
- حفظ تفاصيل مكونات البدلات ومراجع المصدر ضمن دليل خاص بالموظف وملف مطابقة محلي؛ لا رفع بيانات الموظفين إلى مصدر الإضافة القابل للتوزيع.
- مفاتيح مصدر ثابتة عبر XML IDs في `ir.model.data`، مع كشف الأسماء المتكررة وتوقف النطاق المتعارض. إعادة التشغيل لا تنشئ نسخًا جديدة.
- بيانات المصدر للقراءة فقط. لا تغيير Administrator أو جداول الدوام أو الصلاحيات الحالية.

## خريطة الأثر ARCHITECTURAL — HR1

بصير القديم (قراءة) → لقطة محلية محددة بالشركات → تحقق/مطابقة → ORM أودو `hr.employee` و`hr.version` والموارد التابعة الأصلية → قراءة مطابقة.

مرجع النظام: `docs/architecture/registry/INDEX.md`. لا تغيير في مخطط التطبيق أو الكود المجمد أو سلطة الحسابات. عمليات ORM الأصلية تحفظ عزل الشركة والتحقق من الراتب. البيانات تخص هذه المنشأة ولا تدخل حزمة البذرة.

## بوابات التنفيذ

1. جرد المصدر، اختيار البيانات الحالية، كشف التعارضات وتحديد معاني الرواتب والبدلات.
2. تثبيت لقطة المصدر ومعرفاتها وhash، إعداد تحويل قابل للاستئناف، تجربة كتابة ثم rollback، ومراجعة مستقلة للتحويل والأرقام.
3. نسخة احتياطية متماسكة من الأصلية قبل الكتابة؛ نافذة قصيرة لحماية التزامن إذا لزم. لا قفل تشغيلي دائم للشركات القائمة.
4. كتابة ذرية للنطاق الموافق عليه، ثم مقارنة الموظفين والشركات والرواتب والبدلات ومنع التكرار؛ إثبات بقاء العمليات المالية كما هي.
5. توثيق المنقول والمستثنى والنواقص وأماكن ظهور الملفات. لا إعلان الاكتمال إذا بقي نطاق غير مطابق.

## الفريق

- القائد: التنفيذ، التحويل، التشغيل والتوثيق.
- مختص المصدر: جرد مستقل للقراءة فقط ومراجعة معاني بيانات بصير القديم.
- مراجع القبول: مراجعة مستقلة للتحويل ومطابقة البيانات قبل وبعد الكتابة.

## قرار المالك اللاحق — النطاق التنفيذي الملزم

«انقل السابقين كملفات مؤرشفة» ثم «انقل الأسماء فقط حتى نحدد جداول الدوام».

- استيراد الاسم العربي وربط الشركة وحالة نشط/مؤرشف، وحفظ الاسم الإنجليزي ورقم الموظف وحالة المصدر كمرجع إداري غير مالي.
- لا نقل لقيم الرواتب والبدلات أو تواريخ العقود أو تعيين جدول عمل. صفر الراتب الافتراضي يعني ملفًا غير مُعد؛ يوضح المرجع الإداري أن الإعداد مؤجل. حارس نقص تاريخ العقد الحالي يمنع اعتماد الراتب.
- الموظفون في إجازة يبقون نشطين؛ تحفظ حالة المصدر في المرجع فقط، دون إنشاء إجازة أو خصم غير مثبت.
- المصدر المحلي المعتمد `baseer-erp-postgres/baseer_erp_test`، لقطة 51 ملفًا: ARZ=25، الشامي=20، الدوحة=6. 34 حاليون و17 سابقون. جميعها تملك خرائط Noorix مكتملة. بيانات QA وشركات الاختبار خارج النطاق.
- بيانات التعويضات محفوظة محليًا للمطابقة المستقبلية ولا تدخل الاستيراد الحالي. لقطة الأصل الخاص `.local-backups/hr-import-20260909/source.json` SHA256 `a8eda338b31b9947ab69ff275c75f39cd7c5cb3d9922e46309564a8017e8ce13`.
- أربعة ملفات سابقة في الشامي تتشارك اسمين بأرقام مصدر مختلفة؛ وافق المالك صراحة «ادمجهم». يُدمج كل زوج في هدف مؤرشف واحد مع حفظ المرجعين ورقمي الموظف. النتيجة 49 ملفًا مقابل 51 معرف مصدر؛ 34 حاليًا و15 مؤرشفًا.

## التجربة والمعالجة

- التجربة الأولى تراجعت بالكامل: امتداد الرواتب الأصلي يفرض NOT NULL على جدول العقد، فلا يقبل تركه فارغًا.
- معالجة توافق بيانات فقط: ثلاثة جداول أصلية مرنة «بانتظار تحديد الدوام»، أحدها لكل شركة، بساعات يومية وأسبوعية صفر وبلا فترات أو عطلات. هذه ليست تعيينًا لدوام فعلي ولا تغييرًا لجدول الشركة. المصدر البرمجي لم يتغير.
- السياق الأصلي `salary_simulation` يُستخدم لملفات أسماء جديدة بلا عقد أو مدير أو أجور لتجاوز صور avatars وملاحظات التهيئة وخطافات الإجازات/work entries غير المرتبطة بهذا الاستيراد، مع بقاء قيود ORM الأصلية.
- التجربة الثانية: 49 ملفًا، 51 مرجعًا، إعادة تشغيل ثانية بلا إنشاء، 152 جدولًا تشغيليًا/ماليًا أو صفوف جداول الدوام الأصلية دون تغيير. جميع كتابات التجربة rollback. مفاتيح جداول الانتظار مستقلة وقابلة لإعادة الاستخدام.
