# ABROJ-COST-PLAN-IMPORT — استيراد وتصدير دراسة المشروع

الحالة: مرشح QA فقط — لا نشر إلى Live.

## عقد البناء (G0)

- **الهدف:** تمكين مستخدم تكاليف المشاريع من تنزيل نموذج دراسة مشروع، استيراد بنود الدراسة منه بسرعة، وتصدير بنود الدراسة الحالية، من دون إنشاء أو تعديل مواد مكتبة المواد.
- **المستخدم:** مستخدم أو مدير `abroj_project_costing` المخوّل للمشروع والشركة المحددين.
- **داخل النطاق:** نموذج XLSX/CSV، معاينة/تحقق خادمي قبل الكتابة، إنشاء بنود دراسة جديدة لذات المشروع، تصدير البنود الحالية، ورسائل خطأ ثنائية اللغة.
- **خارج النطاق:** استيراد مكتبة المواد، إنشاء فئات جديدة تلقائياً، تعديل بنود موجودة، دمج أسعار أو قيود محاسبية، ونشر Live.
- **معايير القبول:**
  1. تنزيل نموذج يشرح الأعمدة والقيم المسموح بها.
  2. قبول CSV وXLSX صالحين؛ رفض الصيغة أو العمود أو الفئة أو السعر غير الصالح قبل إنشاء أي بند.
  3. لا كتابة جزئية: تتحقق كل الصفوف ثم تنشأ بنودها في معاملة واحدة.
  4. الفئة تطابق فئة موجودة في الشركة المحددة فقط؛ لا تنشأ مادة أو فئة.
  5. تصدير دراسة المشروع يعيد البيانات القابلة لإعادة الاستيراد، مع أرقام غربية ومنزلتين عشريتين كحد أقصى.
  6. عزل الشركة القائم يبقى نافذاً في المعالج وفي البنود المنشأة.
- **الافتراضات:** ملفات حتى 500 صف و5 ميغابايت؛ الاستيراد يضيف البنود فقط ويمنع الاستيراد إلى مشروع مغلق؛ المستخدم يختار المشروع من سجله المرئي.
- **خريطة ERP:** هذه دراسة تقديرية إدارية لا تنشئ قيداً أو دفعة أو مخزوناً. مصدر حقيقة إجمالي التكلفة هو الحقول المحسوبة الخادمية في `abroj.cost.plan.line` ثم `abroj.cost.project`. لا يسمح للاستيراد بالترحيل أو تعديل سجل مالي معتمد.

## ملف السعة والاستمرارية (G1)

- **الرحلة الحرجة:** تنزيل النموذج → رفع ملف ≤500 صف → تحقق خادمي كامل → إنشاء ذري أو عرض خطأ.
- **النمو:** حتى 50 مشروعاً نشطاً للشركة و500 بند دراسة للمشروع في السنة؛ لا يحمل المعالج سجلات غير الملف والفئات المطابقة.
- **التزامن:** لا يعيد المحاولة تلقائياً ولا يحدّث سجلات قائمة؛ كل تنفيذ ينشئ صفوفاً جديدة فقط بعد تحقق شامل. احتمال تكرار رفع الملف يعالج برسالة صريحة عندما يحتوي المشروع على بنود، ولا يحدث دمج صامت.
- **الاستمرارية والرصد:** خطأ الصف يذكر رقم الصف والحقل فقط، لا يحتوي بيانات الملف كاملة؛ Odoo audit (`create_uid`/`create_date`) يظل سجل إنشاء البنود.

## المعمارية والعقود (G2)

```text
ملف المستخدم → معالج مؤقت (اختيار المشروع + ملف)
           → محلل CSV/XLSX → قائمة قيم متحققة (Decimal بمنزلتين)
           → تحقق فئة الشركة/صلاحية المشروع/حد الحجم
           → create متعدد ذري لبنود الدراسة → المجاميع الخادمية الحالية
```

- نموذج المعالج لا يملك مواد ولا ينشئها؛ عمود المادة غير موجود في النموذج.
- الأعمدة: `category`, `name`, `pricing_method`, `quantity`, `material_unit_cost`, `auxiliary_unit_cost`, `labor_unit_cost`, `inclusive_unit_cost`, `lump_sum_cost`, `notes`.
- القيم الرقمية تقرأ بدقة `Decimal`، ترفض السالب وأكثر من منزلتين عشريتين، ثم ترسل إلى حقول أودو الموجودة التي تملك الحساب النهائي.
- ينشئ المصدر الرقم التسلسلي حسب صف الملف. يحتفظ سجل المشروع بحسابه الخلفي ولا يثق بجمع الواجهة.
- لا يستخدم `sudo()` لتجاوز قواعد الشركة أو المشروع.

## قرارات المسار المباشر (G3)

1. **معالج Odoo عابر بدلاً من تعديل يدوي/واجهة JavaScript:** يستفيد من صلاحيات السجل، معالجة الملفات، وتحديث الموديول، وهو الأقصر والأقل مخاطرة.
2. **CSV وXLSX بدل خدمة خارجية:** لا نقل بيانات ولا حساب سحابي ولا اعتماد إضافي.
3. **إضافة فقط مع منع الاستيراد إلى خطة غير فارغة:** يمنع تكرار البنود والتعديل الصامت؛ ستُصمم عمليات الاستبدال الجماعي لاحقاً إذا طلبها المالك.

## تجربة الاستخدام (G4)

- زران في رأس المشروع: «استيراد دراسة» و«تصدير دراسة».
- نافذة الاستيراد: المشروع (مقفل من السياق)، رابط تنزيل النموذج، رفع الملف، زر «تحقق واستيراد»، زر إلغاء، ورسالة نتيجة بعد الحفظ.
- تعتمد أزرار ورفع ملف وحوار Odoo القياسية؛ لا CSS أو JavaScript جديد.
- قالب XLSX يحتوي ورقة `بنود الدراسة` وورقة `التعليمات`، وCSV يحمل صف العناوين نفسه.
