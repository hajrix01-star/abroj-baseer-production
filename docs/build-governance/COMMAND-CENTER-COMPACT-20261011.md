# مركز القيادة المختصر — التصميم المعتمد

## G0–G3 للمراجعة قبل الكود

- G0: تنفيذ التصميم الثاني المعتمد، شركة مختارة ببطاقة مختصرة، متوسط للطلب وللعميل؛ الأيام مطوية افتراضيًا وتعرض التاريخ وصافي المبيعات شامل الضريبة وعدد العملاء ومتوسط العميل دائمًا. داخل اليوم جلسات مطوية وتفاصيل الإلغاءات والاستبدالات. لا تغيير طلب/جلسة/قيد، ولا نشر إنتاج بهذا الطلب.
- خريطة الأثر: pos.order + pos.session (صلاحيات المستخدم/الشركة) → executive.py تجميع SQL numeric/Decimal → عقد بطاقة/أيام/جلسات → Owl/XML/SCSS. سجلا الاستبدال وإلغاء الصنف optional read-only. المعمارية الأصلية COMMAND-CENTER-SESSION-DAY باقية، اليوم هو تاريخ فتح الجلسة بتوقيت الرياض.
- G1: استخدام المالك شخصي لشركات صغيرة؛ حدود قائمة 3 شركات/طلب و366 يوم و100kطلب و50جلسة/صفحة. الأيام مجاميع محدودة≤366، الجلسات تجلب عند فتح اليوم فقط مع ترقيم مستقل. لا مكتبة/schema/بيئة/حمل جديد. خطر جديد: تجميع عدد العملاء ومفاتيح التاريخ لا السعة العامة؛ اختبار محدد للفروق فقط.
- G2: صافي المبيعات المصدر المؤكد paid/done/invoiced كما هو، refunds تدخل بإشارتها دون تكرار الفاتورة. عدد العملاء=SUM(customer_count الموجب) للطلبات غير المرتجعة، ليس عدد شركاء فريدين. وجود بيع بلا customer_count موجب يجعل عدد العملاء/متوسط العميل غير متاحين (مع العدد المسجل منفصلًا إن لزم)؛ لا تعويض بعدد الطلبات. متوسط الطلب=صافي المبيعات/عدد طلبات البيع غير المرتجعة؛ صفر مقام غير متاح. متوسط العميل=صافي المبيعات/العدد المسجل الكامل. Decimal ومصدر formatter مشترك، لا حساب مالي في JS.
- الأيام تعرض المجاميع لكل الفترة لا آخر14يوم فقط؛ الرسم يبقى آخر14يوم. صفحة الجلسات عند فتح يوم تحدد from=to=day، فتظل مجاميع اليوم كاملة ومستقلة عن ترقيم الجلسات. العميل لا يجمع صفحة الجلسات لإنتاج إجمالي اليوم.
- الإلغاءات: عدد الطلبات state=cancel مستقل عن عدد أحداث إلغاء الصنف في baseer.pos.protected_item_cancellation، والاستبدالات عدد أحداث baseer.pos.substitution لا المرتجعات ولا كميات الأصناف. كل سجل بحسب الشركة والجلسة المرئية وتاريخ فتحها، ACL/record rules دون sudo. النموذج غير مثبت أو حق القراءة غير متاح يعرض غير متاح لا صفر؛ إلغاء الطلب لا يدخل صافي المبيعات.
- G3: Odoo19/SQL/Owl/Bootstrap/FontAwesome القائمة فقط، لا اعتماد UI جديد. إعادة استخدام formatter و_tokens/buttons الحالية. G4 عبر emil-design-eng: بطاقات صغيرة، تباين وتركيز واضح، details/summary أصلي، 44px لمس، RTL/LTR و0–9، بلا حركة زائدة. لا bottom-nav أو هوية جديدة من صور التصور؛ تبقى قشرة Odoo.
- القبول: 1200/10=120 و1200/12=100؛ التقريب Decimal، مردود/مقام0/عدد عميل ناقص، حدود فترة منتصف الليل والجلسة الطويلة، شركتان وصلاحيات، optional audit models، اليوم المغلق يظهر الثلاثة، فتح اليوم يعرض جلساته وحدها، تبديل الشركة والفلتر لا يترك نتائج قديمة، عرض390/1280 عربي/إنجليزي بدون overflow.
- الرجوع: المصدر السابق للموديول، لا migration أو بيانات تشغيلية. G0–G3 قيد مراجعة مستقلة قبل كتابة حاسبة جديدة؛ G5–G8 معلقة.
- توضيح المصدر: حقل customer_count/is_refund يُكتشف إن كان مثبتًا؛ عند غيابه لا يفشل مصدر المبيعات وتكون مقاييس العملاء غير متاحة. تفاصيل الجلسات تستخدم نطاق جلسات مرئية مستقلاً بنفس تاريخ الفتح، فتشمل جلسات فيها إلغاءات فقط أو بلا بيع، ولا تضيفها للمبيعات. عدد sessions الإجمالي وعناوينه يتغير إلى الجلسات في الفترة لا «ذات المبيعات»؛ audit counts تشمل الجلسة دون اشتراط حالة بيع، مع تقاطع order/session record rules. كل SQL جديد يطابق _search ولا يتجاوز ACL.
- تصحيح حارس البوابات: visible_session_domain=الشركة+قواعد القراءة+start_at ضمن حدود يوم فتح الرياض≤now؛ منه قائمة الأيام وعدد الجلسات وترقيمها، ثم إثراء بمجموعة البيع وcancel/audit دون اشتراط وجود بيع. قبول لازم: يوم/جلسة صفر مبيعات وفيها إلغاء تظهر بمبيعات0، ومتوسط غير متاح عند مقام0. لا يُستخدم COUNT DISTINCT من salesquery لتعداد جلسات الفترة.
