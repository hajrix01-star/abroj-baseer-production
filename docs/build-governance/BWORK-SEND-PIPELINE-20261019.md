## الأثر والعقد قبل التنفيذ

حسابات أو ضغط الصورة. مالكو التنفيذ: core وحصيلة flush؛ useChat وجدولة

الاستخدام، ولا إعادة اكتشاف أو فحوص خادم/حمل بلا فرق يستدعيها.

1. إشارة الإرسال أثناء دورة جارية تُجمع فقط لـUUID جديد queued ومستحق،
   وتُستهلك بعد نجاح الدورة فورًا، دون توازي طلبات أو تخطي backoff أو حلقة
   لنفس UUID. تتوقف عند الخلفية/offline/فشل/تبدل سلطة الحساب أو unmount.
2. `FlushResult.historyFor(room)` حصيلة محلية من post-ACK readHistory ناجح
   فعلًا، لا rememberedHistory أو صفحة من caller. آخر لقطة واحدة لكل غرفة؛
   epoch/accountScope/room/company/member/TTL/chat_view وwindowVersion
   ومرجع history الداخلي تحرس استعمالها. نسخة دفاعية أو null للغياب/تغير
   اللقطة، ورفض للسلطة القديمة. fallback قراءة UI العادية عند عدم صلاحيتها.
   لا تغيير ترتيب ACK/durable outbox أو سلوك التصفح/الأرشيف أو حقوق النص.
3. معاينة الصورة المعلقة من actual pending UUID والـstage الخاص فقط، لا
   URI من الواجهة ولا media ID مصطنع. foreground/عضوية/view+send+media
   وملكية/حجم/SHA وحالة pending بعد الانتظار مطلوبة. 240×180 مع بقاء
   الساعة الحقيقية؛ لا HTTP أو copy/pin أو تغيير ملكية/تنظيف stage. نتيجة
   متأخرة أو onError لا تحذف ملفًا ولا outbox ولا تعيد المعاينة في حلقة.
