## G2 العقد والـ ERP
تبقى حقول Char وواجهة record.update الأصلية، ولا تحويل إلى datetime أو timezone. يعرض المنتقي أرقامًا غربية وصيغة24h في العربية والإنجليزية. لا تحسب الواجهة مدة/أجرًا. تغيير القيمة يستدعي onchange الخلفية ويظهر الإجمالي الوارد منها. لا يُطبّق وقت افتراضي صامت عند مجرد فتح المنتقي أو إلغائه. تبقى صلاحيات WS1 والنسخ التاريخية محفوظة.

## G3–G4 المسار المباشر — قيد مراجعة المصدر الأصلي
الأولوية لإعادة استعمال TimePicker/Popover من Odoo19 بترخيصLGPL؛ لا مكتبة جديدة ولا تعديلcore. المراجع المستقل schedule_architecture يفحص قدرة المكون على24h/minute/RTL والتحكم بالقيمة. بنّاء الواجهة هو root، والمراجع مستقل. الحالات: قراءة فقط، فتح، اختيار، تأكيد، إلغاء/Escape، منتصف الليل، نهاية24:00، جوال/كمبيوتر. لا حركة إضافية. استخدام مكونات Odoo المركزية المعتمدة في WS1 وتطبيق مبادئ emil-design-eng على الوضوح واللمس.

## السجل
1. قُرئ طلب المستخدم والصورة؛ سبب المشكلة إمكانية كتابة09 أو15 بدلHH:MM. فُحص CharField وPopover الأصليان وملف الإضافة؛ لا تعديلات تطبيق قبل مراجعةG0–G4. المشروع الحالي والمصدر المجمد WS1 هما المرجع.

2. مراجعة المصدر المستقلة — schedule_architecture، 2026-09-09: يوجد `@web/core/time_picker/time_picker` في المصدر المحلي وفي حاوية الأصلية المثبتة. فحص `getSuggestions` يثبت أن minutesRounding بقيمة1 لا يتيح كل الدقائق في القائمة بل يقفز15 دقيقة؛ و`Time.toString()` يتبع صيغة اللغة، و`parseTime('24:00')` يحوله إلى00:00. حقل float_time مخصص لـFloat وليس Char. لذلك لا يحقق استعمال هذه المكونات دون تعديل شروط العقد، ولا يعتمد الحل على تغييرها عالميًا أو تغيير إعداد اللغة.
3. قرار المسار المباشر الذي يحل محل اقتراح TimePicker/Popover في مسودة G3–G4: widget Char مركزي واحد في نفس الإضافة، يعرض عنصرَي HTML select أصليين بتنسيق Odoo، أحدهما للساعات00–23 والآخر لكل الدقائق00–59. حقل النهاية فقط يتيح الساعة24 ويثبت الدقيقة00 ويعطل اختيارها عند24؛ يرسل النصASCIIHH:MM عبر record.update. القراءة فقط تعرض النص. الاختيار يغير قيمة الإدخال مباشرة؛ لا popup مخصص ولا خطوة تأكيد/إلغاء جديدة ولا إدخال نص حر. فتح قائمة المتصفح أو إغلاقها لا يغير القيمة. لا بيانات جديدة ولا migration ولا مكتبة جديدة ولا تحويل datetime أو تعديل منطقة زمنية. المقادير والحسابات تبقى في الخلفية.
4. اعتماد البوابات المستقل: **G0 وG1 وG2 وG3 وG4 معتمدة** لهذا النطاق المحدود. المراجع ليس منفذ widget. السبب: عقد HH:MM الأصلي محفوظ، وعناصر select تحدد الاختيارات الخام فقط، ولا تضيف مصدر حقيقة حسابية. السعة القصوى28فترة تعني قوائم صغيرة ثابتة من24/25ساعة و60دقيقة لكل حقل، ولا شبكة أو مؤقتات إضافية. يعتمد عنصر مركزي واحد يعاد استعماله في جدول سطح المكتب ونموذج الفترة المحمول للقالب والموظف، مع labels عربية/إنجليزية وLTR للأرقام ومؤشر تركيز واضح وحجم لمس ملائم.
5. شروط قبول التنفيذ G5–G8: إثبات فعلي للعربية والإنجليزية على الكمبيوتر والجوال؛ ساعات21:00→03:00، دقائق غير ربعية مثل09:07→15:43، ونهاية24:00 مع منع24:01، وتبديل24إلى ساعة عادية، وقراءة الوقت المحفوظ دون تغيير، وعدم تعديل القيمة بمجرد فتح/إغلاق الاختيار. اختبار تغيير الساعة والدقيقة بسرعة للتأكد من أن onchange غير المتزامن لا يفقد إحدى القيم. تبقى معاينة الإجمالي من الخلفية، وتختبر صحة الاستيراد والقراءة فقط والأرقام الغربية وعدم overflow. لا تعاد مصفوفة107فحصًا خلفيًا أو اختبار التزامن ما دامت ملفات المنطق والعقود الخلفية مطابقة لـWS1؛ يلزم فحص تكامل محدود للإرسال والمعاينة بالإضافة إلى بناء الأصول والتحقق من الواجهة. أي تغيير في الحساب أو صلاحية أو حفظ بيانات يعيد فتح G2 قبل تنفيذه.
